# Установка, первый запуск и обновление

Первый запуск: **USB → точка доступа S3 → домашний Wi-Fi → добавление C3**. Начните с одного Hub без C3. Нагрузки при установке отключены, GPIO насоса по умолчанию не назначены.

## Программа для Windows, Linux и macOS

Нужен Python 3.10+ и USB-кабель с передачей данных. Для Linux может потребоваться доступ пользователя к группе последовательных портов; для Windows — драйвер USB конкретной платы. ESP32-S3: выберите профиль **n8r2** (8 MB flash, Quad PSRAM) или **n16r8** (16 MB flash, Octal PSRAM) по маркировке. Не используйте только название «S3» для выбора образа.

В папке проекта установите зависимости (на macOS/Linux замените `python` на `python3`, в Windows можно использовать `py -3`):

```sh
python -m pip install -r tools/requirements-flash.txt
python tools/flash.py
```

Также доступны `flash.cmd` и `./flash.sh`. Программа показывает последовательные порты, спрашивает профиль и каталог USB-пакета. Пакеты содержат приложение, загрузчик, таблицу разделов и manifest с SHA-256; секретов в них нет. Для готового пакета SDK не нужен. Если пакета ещё нет, Enter вместо каталога запускает сборку из исходников — тогда требуется активированный **ESP-IDF 5.3.4**.

Меню разделяет три действия:

1. **Первая установка Hub** — только для новой платы с пустым NVS. Индивидуальный ключ администратора и сертификат создаются автоматически; пароль AP — smartplantos.
2. **Обновить прошивку** — только приложение, с сохранением NVS и разметки. Поддерживает действующие S3/C3 установки.
3. **Подготовить новый C3** — USB-настройка нового контроллера по паспорту Hub, затем импорт файла привязки в браузере.

Непустой NVS при первой установке не стирается автоматически. Даже новая покупная плата может иметь заводскую прошивку и NVS. В таком случае мастер остановится; это не повод запускать erase для работающей системы. Для намеренного сброса есть отдельный режим `factory-reset`; он уничтожит прежние ключи и потребует новой установки.

## Первый запуск S3

1. Подключите S3 по USB. В мастере выберите первую установку, её порт и профиль. Подтвердите `INSTALL`.
2. Программа покажет путь к приватному каталогу `secrets/hub-…/access.json`. В нём пароль точки доступа, ключ администратора и SHA-256 сертификата. Каталог хранится локально и не попадает в Git.
3. Подключите телефон/компьютер к **SmartPlantOS**, пароль **smartplantos**.
4. Откройте **https://192.168.4.1/setup**. Сертификат самоподписанный: перед подтверждением проверьте отпечаток по USB-комплекту. Для нового LAN IP браузер тоже может показать предупреждение — сертификат содержит адрес AP, доверенного LAN-имени пока нет.
5. Импортируйте `access.json` в поле входа или введите ключ администратора. Сам файл не отправляется на Hub; страница использует ключ только для входа.
6. Введите имя домашней сети **2,4 ГГц** и пароль. Hub проверяет подключение до 30 s. Credentials сохраняются после получения IP. При неудаче активная прежняя сеть восстанавливается; AP работает во время пробы; после успешной связи выключается через 30 s, а после потери домашней сети включается через 60 s.
7. При смене канала телефон может потерять связь с AP. Повторно подключитесь к SmartPlantOS и откройте `/setup`. В статусе появится IP домашней сети. Пароль не возвращается из API.

Сканирование списка SSID, WPA-Enterprise, открытые сети и mDNS этим шагом не добавлены. Пароль домашней сети — 8–63 печатных ASCII-символа, SSID — до 32 UTF-8 байт. C3 подключаются к S3 по ESP-NOW, пароль роутера им не передаётся.

## Добавление C3 через веб-интерфейс

1. На `/setup` скачайте **паспорт Hub**. Это публичный JSON без ключей.
2. На компьютере подключите новый C3. В терминальном мастере выберите подготовку C3, его порт, пакет `c3` и файл паспорта.
3. Программа проверяет чип/flash и пустой NVS. Создаёт индивидуальные случайные LMK/app key; ключи передаются C3 по USB. Насос остаётся отключён.
4. После подтверждения `INSTALL` программа сохраняет приватный **node-pairing.json** и показывает его путь. Импортируйте файл на `/setup` вашего Hub.
5. Hub проверяет свой ID, уникальность MAC/ID C3 и вместимость реестра. Связь сохраняется отдельным атомарным NVS blob. Повторный импорт не заменяет ключи и не обнуляет счётчики.

Файл привязки равнозначен секрету конкретного C3. Не прикладывайте его к issue, Git, снимкам экрана или логам. На Unix приватные файлы создаются с правами 0600, каталог 0700; на Windows используйте личный каталог с подходящими ACL. Полностью беспроводное discovery/pairing ещё не реализовано. Удаление/перепривязка существующего C3 требует отдельной процедуры, а не повторной первичной установки.

## Обновление действующей установки

```sh
python tools/flash.py update --port COM5 --profile n8r2 --bundle path/to/usb-package
```

Мастер проверяет чип, размер flash, профиль пакета, SHA-256 файлов и установленную таблицу разделов, затем показывает операцию и просит `UPDATE`. В режиме update единственная запись — приложение. NVS, replay epochs, registry, Wi-Fi и лимиты остаются на своих адресах. При несовпадении разметки обновление отклоняется. Насос должен быть отключён физически; USB-проба перезапускает чип.

SHA-256 выявляет повреждение пакета, но не доказывает авторство. Используйте пакет из доверенного источника; подписанные релизы и Secure Boot здесь не реализованы.

Текущая factory-разметка не обеспечивает откат образа. При обрыве USB/питания повторите USB-обновление. Нельзя восстанавливать старый дамп NVS с прежними ключами. Web OTA потребует отдельного перехода на два app-слота/otadata и проверки rollback.

## Сборка пакета разработчиком

После сборки нужного профиля:

```sh
python tools/package_firmware.py --build firmware/hub/build/install-n8r2 --profile n8r2 --output firmware/hub/build/usb-package-n8r2
```

Для C3 укажите профиль `c3` и каталог его сборки. Упаковщик проверяет flash/PSRAM настройки S3, добавляет manifest. В пакет не включаются `access.json`, NVS и файлы привязки. См. [контракт настройки](../spec/setup/v1/README.md) и [ADR-0013](adr/0013-setup-and-preserving-updates.md).

## Восстановление точки без сброса

```sh
python tools/flash.py setup-ap --port COM5
```

USB-команда открывает AP на 5 минут, затем применяется обычный grace-период. Ключ администратора остаётся прежним.

## Намеренный заводской сброс

```sh
python tools/flash.py factory-reset --port COM5 --profile n8r2
```

Мастер проверит плату и разметку, затем потребует `RESET <MAC>`. Удаляются ключи, связи, сеть, настройки и история; сохраняется приложение. Выполните новую установку, получите новый access.json и заново подготовьте C3. Старые NVS-образы не восстанавливайте. Для обновления используйте режим update. См. [ADR-0014](adr/0014-setup-ap-lifecycle-and-reset.md).

## Последовательный мастер

На адресе точки SmartPlantOS корень `/` перенаправляет на `/setup`: растения не доступны через точку настройки. Сервер определяет интерфейс по локальному адресу принятого TCP-соединения, а не по Host. В мастере сначала вводят ключ, затем настраивают Wi-Fi. Только подтверждённое подключение и сохранение настроек открывает финальный шаг с домашним адресом `https://<IP>/`. Переключение телефона на домашнюю сеть выполняется вручную. Браузер не получает доступ к настройкам Wi-Fi телефона.

Добавление C3 и инструкции обновления открываются на `/setup` из домашней сети после входа и подтверждённого подключения. До этого они скрыты. Ключ не сохраняется в localStorage/sessionStorage; обычное USB-обновление сохраняет ключ в NVS. Это адаптивное браузерное приложение; установка PWA и автоматическое открытие captive portal пока не реализованы.
