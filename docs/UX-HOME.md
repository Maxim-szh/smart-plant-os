# Домашний интерфейс: визуальная система и сценарии

Дата: 2026-11-05. Улучшение существующей OS, не смена оформления и не объединение с demo.

## Визуальное направление до реализации

Ориентиры: исходный home-desktop.png и созданный через frontend-app-builder/Image Gen макет комнат. Палитра зафиксирована: bg #F0F2EC, surface #FAFBF8, tx #17201B, tx2 #4F5F56, pri #2C6A4F, border #D9DED4. Тёмная тема использует существующие токены. Арки, горшки, SVG растений и существующие иконки остаются нативными, новые bitmap-иллюстрации в прошивку не добавляются.

Literata: заголовок 34/1.15, названия комнат 22/1.3, название растения 20/1.25. Onest: основной текст 16/1.5, пояснения/поля 14/1.45, навигация 12/1.3. Контролы определяют свой шрифт явно, поля на телефоне не меньше 16px, touch-target не меньше 44px. Интервалы 8/12/16/24/32, радиусы существующей системы 6/10/16/28. Длинные русские имена переносятся; кнопки не обрезаются.

Глобальная навигация: Растения → Дневник → Уход → События → Настройки. На главной: «Мои растения», «Ваш сад и последние данные от устройств.», «Добавить растение», фильтр «Все комнаты», «Дневник ухода», группы по комнатам, «Последние записи». В карточках: русское имя/вид, существующая арка, реальные статус/измерение, «Записать уход», «Дневник». Декоративные проценты и фиктивная телеметрия запрещены.

На desktop комнаты занимают основную область, последние записи — боковую колонку. На мобильном блоки идут последовательно, карточки доступны без горизонтального переполнения всей страницы. В дневнике: «Дневник ухода», «Ваши записи о растениях.», «Добавить запись», фильтр по растению, редакционные строки с датой/растением/заметкой. При отсутствии записей — честное пустое состояние.

## Сценарии

[Контракт](../spec/experience/v1/README.md). Дневник доступен из навигации, главной и карточки. Быстрые действия только создают запись после подтверждения. Комнаты группируются и сворачиваются; перенос сохраняется на Hub с защитой ревизий.

Обслуживание — подтверждённый ручной режим C3 с отдельной отметкой Hub. После завершения остаётся manual, автоматическое возобновление не реализуется. Чек-лист, черновики и совместимость из CARE-CHECKS.md сохраняют прежнюю ответственность.

Мастер нескольких растений не стирает черновик на каждом poll. После online можно описать растение и продолжить поиск следующего; настройка GPIO/датчиков не считается выполненной этим описанием.

## Допустимые отличия от Image Gen

Существующие точные SVG, иконки, цвета и радиусы имеют приоритет над неточными деталями генерации. Ботанические картинки не заменяются сгенерированными фотографиями. Данные концепта — только тестовые сущности для визуального сравнения, реальная панель берёт API. Сезонная дата не добавляется только ради макета. Пустой дневник использует простую иконку книги, без новой декоративной арки; лишний переход «Перейти к уходу» не добавляется. Это сохраняет исходный дизайн и экономит память S3.

## Адаптивная доработка 2026-11-06

Существующий интерфейс служит визуальным ориентиром: палитра, Literata/Onest, SVG растений, радиусы и состав разделов сохранены. Новый графический концепт не требуется — исправляется компоновка внутри принятой системы.

- Общие кнопки допускают перенос текста и имеют внутренние вертикальные отступы; длинные имена, названия комнат и строки событий не вытесняют соседние контролы.
- На телефоне изображение растения находится рядом с именем и состоянием. Неактивная фиксированная кнопка насоса заменена пояснением в потоке: она не закрывает показания и навигацию.
- «Записать уход» и «Дневник» остаются на карточке; перенос и обслуживание раскрываются через «Ещё действия», без всплывающей панели поверх соседних растений.
- Выбранный раздел заметен в обеих навигациях. При переходах запоминается прокрутка раздела/растения на время открытой страницы. Вкладки растения связаны с панелью через ARIA, поддерживают стрелки/Home/End и сохраняют фокус при загрузке данных.
- Диалоги используют общие отступы и закреплённый заголовок с закрытием. Фоновая страница не прокручивается; высота ограничена динамическим viewport. Первичная настройка учитывает узкий экран и safe-area; checkbox не растягивается общими правилами текстового поля.
- У оболочки приложения учтены safe-area сверху/снизу и по бокам, короткие/ландшафтные окна; API и команды не кэшируются, Service Worker не добавляется.

Проверка: `tests/web-responsive.cjs` с изолированным API — все пять разделов на 320/390/768/1024/1440 px, длинные метаданные, раскрытие действий, диалоги, окно 844×390, клавиатура, восстановление прокрутки, тёмная тема и первый запуск. Сравниваются исходные и новые рендеры: композиция, типографика, палитра, исходные иллюстрации/иконки, отступы и иерархия действий. IAB использован для ручного прохода мобильной карточки; полные desktop-снимки и регрессии выполнены Playwright в локальном Chromium, поскольку снимок IAB ограничен размером панели приложения. Физическая установка PWA и экранная клавиатура iPhone требуют отдельной проверки на телефоне: короткий viewport в тесте не подменяет эту проверку.

### Детали форм и служебных экранов

После проверки реального интерфейса дополнительно исправлены редактор доступа браузера, список устройств, выход из приложения и дневник. Общая анатомия формы: подпись → поле с интервалом 6 px → отдельная группа действий с отступом 16 px и gap 12 px. На узком экране действия доступа располагаются друг под другом. Сведения устройства используют явно заданный Onest 16 px; название растения — существующий Literata. Неизвестная версия подписана «Не получена», а служебные сообщения очищаются при смене панели.

В дневнике выбор вида записи имеет рамку и явное выбранное состояние, редактор отделён от истории, у заметки есть подсказка по контексту. Дата и текстовые поля используют Onest 16 px, включая WebKit-внутренности поля даты. Выбор типа фокусирует заголовок формы, а не вызывает клавиатуру. Успешное сохранение подтверждается; защита черновиков и отсутствие автоматических повторов сохраняются. Редактор имени браузера поддерживает Enter, не отправляет пустое имя, защищает черновик при обновлении списка и снимает признак несохранённости только с успешно сохранённой формы.

Адресная проверка: `tests/web-details.cjs` — 320/390/1440 px, светлая/тёмная тема, интервалы по фактической геометрии, шрифты полей, сохранение/проверка имени, переключение типа записи с черновиком и сохранение дневника. Регрессии затрагивают access, garden, care, home, system и responsive. Визуальная сверка охватывает поля/кнопки, типографику, выбранное состояние, разделение редактора/истории и исходные цвета/иконки; новое оформление не вводится.

### Первый экран и состояния событий

Начальная загрузка использует спокойный экран без карточки: Literata 24–30 px, пояснение Onest 14 px и небольшой индикатор. HTML до запуска JS и состояние загрузки приложения совпадают; данные не задерживаются ради анимации, reduced-motion сохраняется.

История событий читается с Hub независимо от текущей телеметрии C3. Пустой успешный ответ означает «Событий нет»; ошибка API означает «События недоступны» с явным обновлением. Загрузка показывается только до подтверждённого результата или при повторе ошибки, а известное пустое состояние остаётся на экране во время фонового чтения. Проверка `tests/web-events.cjs` воспроизводит offline/503 для состояния C3, задержку истории, пустой результат, отказ и восстановление API, а также историю в карточке растения. Сертификат и системное доверие не меняются оформлением страницы.
