# Безопасность: решения до прошивки

Инженерный профиль реализует только физическое USB provisioning и попарно защищённый SPP: [ADR-0010](adr/0010-engineering-firmware-profile.md), [формат кадра](../spec/spp/v1/README.md). Это не законченные пользовательская привязка и браузерная авторизация. HTTP в профиле отсутствует; секреты NVS пока не защищены от физического чтения. Сбрасывать/откатывать NVS со старыми ключами нельзя: это нарушает уникальность AEAD nonce и обнуляет защитные лимиты. Нельзя «чинить» ошибку автоматическим `nvs_flash_erase()`.

Полив — физическое действие. Команды насосу и изменение защитных настроек не могут быть доступны анонимному клиенту. Обязательная основа: уникальные ключи каждой пары Hub ↔ Node, привязка с физическим подтверждением, возможность отозвать привязку, защита от повторного воспроизведения, ограничение частоты команд и журнал авторизованных действий. Секреты не возвращаются через `GET /config`, не пишутся в обычный журнал и не хранятся в Git. Примеры в `spec/v1` содержат только вымышленные идентификаторы.

В CI никогда не хранить реальные ключи устройств.

## Две границы доверия

В новой архитектуре ([ADR-0001](adr/0001-roles-hub-node.md)) API на узле нет, поэтому раздел из прежней редакции про HTTPS на ESP32-C3 (около 40 КБ RAM на соединение по документации Espressif) для Node больше не применяется. Остаются две отдельные границы.

**1. Hub ↔ Node по ESP-NOW.** По документации Espressif шифрование относится к паре с общим LMK; шифрование multicast не поддерживается, а про broadcast документация не говорит. Поэтому поиск и привязка считаются открытым неаутентифицированным каналом, а шифрование канала не заменяет защищённую привязку. Направление — [ADR-0004](adr/0004-pairing-and-keys.md) (статус «Предложено»): физическое подтверждение, аутентифицированный обмен ключами, отдельные ключи уровня SPP, защита от повторов, сохранение счётчиков сообщений после перезагрузки, удаление и сброс привязки.

**2. Браузер ↔ Hub.** Изменяющие маршруты требуют аутентификации; первый вход требует физического действия; сессии ограничены по времени; защита от межсайтовых запросов; изменение защитных настроек подтверждается пользователем. Транспорт (пароль точки доступа, HTTPS с закреплением сертификата, собственный центр сертификации) выбирается после измерения памяти Hub. Направление — [ADR-0009](adr/0009-browser-access-to-hub.md) (статус «Предложено»). Обычный HTTP с постоянным токеном в локальной сети не считать производственным режимом.

## Что не доверяется

- Hub, веб-интерфейс, ИИ и Home Assistant не включают насос напрямую: Node проверяет каждую команду по своим жёстким пределам и текущему состоянию.
- ИИ и интеграции могут предлагать изменения, но не применяют их без подтверждения пользователя; защитные настройки (максимальное время насоса, порция, суточный лимит, интервал) меняются только с явного подтверждения.
- Устаревшая команда полива отклоняется по сроку действия.

## Не проверено

Ни привязка, ни шифрование, ни доступ браузера не реализованы и не измерялись. Доступность криптопримитивов (обмен ключами, вывод ключей, AEAD) в выбранной версии ESP-IDF, их размер и стойкость процедуры независимо не оценивались. До закрытия ADR-0004 и ADR-0009 прошивку, принимающую команды насосу, не выпускать.
