# Первая прошивка и обновление: пошагово

Инструкция для **ESP32-S3 N16R8 (Hub)** и **ESP32-C3 Super Mini (Node)**. Нужны обе платы для проверки веб-приложения и обмена; один C3 можно проверить через USB. Не путайте ESP32 Super Mini на C3 с платами на других чипах. Сейчас это инженерная версия, без завершённых аппаратных испытаний.

Первый проход выполняйте **без насоса, клапана и других нагрузок**. Без назначенных GPIO прошивка позволяет проверить загрузку, связь и интерфейс, но блокирует полив. Точные выводы намеренно не заданы за вас.

## 1. Подготовьте компьютер

Нужны Git, Python, USB-кабель с передачей данных и **ESP-IDF v5.3.4**. Arduino IDE и PlatformIO для этой инструкции не нужны. Для создания сертификата веб-интерфейса нужен OpenSSL с поддержкой `req -addext`.

- Windows: установите ESP-IDF 5.3.4 через официальный установщик и откройте **ESP-IDF PowerShell**, а не обычный терминал.
- Linux/macOS: установите системные зависимости по [инструкции Espressif](https://docs.espressif.com/projects/esp-idf/en/v5.3.4/esp32/get-started/index.html), затем:

```sh
git clone --branch v5.3.4 --recursive https://github.com/espressif/esp-idf.git
cd esp-idf
./install.sh esp32c3,esp32s3
. ./export.sh
cd ..
```

В новом терминале Linux/macOS снова выполните `. /путь/к/esp-idf/export.sh`. Убедитесь, что `idf.py --version` показывает **5.3.4**, а `openssl version` работает. На Windows при отсутствии OpenSSL установите его отдельно; не используйте случайные сертификаты из интернета.

```sh
git clone https://github.com/Maxim-szh/smart-plant-os.git
cd smart-plant-os
```

Для тестирования ещё не слитого PR переключитесь на **точную ветку этого PR**. Не смешивайте Hub и Node из разных версий. Команды далее запускаются из корня `smart-plant-os`, если прямо не указано другое.

## 2. Найдите USB-порты

Подключайте по одной плате и запишите, какой порт появился:

```sh
python -m serial.tools.list_ports
```

Примеры: `/dev/cu.usbmodem...` на macOS, `/dev/ttyACM0` на Linux, `COM5` на Windows. Далее **PORT_C3** и **PORT_S3** — обозначения для замены вашим портом, не буквальные имена. Закройте другие serial monitor перед прошивкой.

На S3 используйте разъём native USB/USB Serial-JTAG, если плата имеет несколько разъёмов: текущая консоль настроена на USB Serial-JTAG. Уточните маркировку платы и наличие 16 MB flash / 8 MB octal PSRAM. На C3 ожидается 4 MB flash. Нельзя переносить эти настройки на неизвестную плату только по внешнему сходству.

## 3. Соберите обе прошивки

```sh
cd firmware/node
idf.py set-target esp32c3
idf.py build
cd ../hub
idf.py set-target esp32s3
idf.py build
cd ../..
```

Успех — сообщение `Project build complete`. `set-target` нужен при первой подготовке каталога или смене target; запускать его при каждом обновлении не нужно. Он пересоздаёт конфигурацию сборки, поэтому не используйте его вместо осознанного изменения `sdkconfig`.

## 4. Прошейте приложения и запишите MAC

```sh
cd firmware/node
idf.py -p PORT_C3 flash monitor
```

После загрузки запишите **STA MAC** из строки `Smart Plant Node ... STA MAC ...`. На новой плате ожидаемо появится `LOCKED: physical provisioning required or NVS invalid; no pump/no radio`: ключи ещё не записаны. Выйдите из monitor сочетанием **Ctrl+]**.

```sh
cd ../hub
idf.py -p PORT_S3 flash monitor
```

Аналогично запишите STA MAC Hub, затем Ctrl+] и `cd ../..`. Не подставляйте вместо STA MAC адрес точки доступа. Если загрузка слишком быстрая, нажмите RESET после открытия monitor. После прошивки USB-порт иногда меняется — повторите шаг 2.

## 5. Создайте новую установку

**Этот шаг и запись NVS ниже — только для первоначальной настройки новой стендовой установки.** Не восстанавливайте старый файл NVS на работающую систему: вместе с ним откатятся счётчики шифрования, дедупликация и ограничения воды. Обычное обновление описано отдельно в шаге 10.

Замените оба адреса на записанные STA MAC. `RU` замените на код вашей страны; выберите разрешённый канал 1–11. Для всех плат одной установки канал одинаковый.

```sh
python tools/provision.py --hub-mac 02:00:00:00:00:01 --node-mac 02:00:00:00:00:02 --country RU --channel 6 --web --output secrets/bench-01
```

Скрипт создаёт индивидуальные ключи обмена, `hub.csv`, `node-0.csv`, `manifest.json`, сертификат Hub и `access.json`. Последний содержит пароль Wi-Fi, ключ администратора и SHA-256 отпечаток сертификата. Не публикуйте эти файлы. Каталог `secrets/` исключён из Git. Повторная генерация поверх существующего каталога запрещена.

Для нескольких растений повторите `--node-mac` (до десяти C3). Порядок задаёт `node-0`, `node-1` и номера `peer` в консоли. Пока не передавайте `--pins`: весь первый тест проводится с выключенным аппаратным управлением.

## 6. Преобразуйте настройки в NVS

Linux/macOS, из корня репозитория:

```sh
python "$IDF_PATH/components/nvs_flash/nvs_partition_generator/nvs_partition_gen.py" generate secrets/bench-01/hub.csv secrets/bench-01/hub.nvs.bin 0x20000
python "$IDF_PATH/components/nvs_flash/nvs_partition_generator/nvs_partition_gen.py" generate secrets/bench-01/node-0.csv secrets/bench-01/node-0.nvs.bin 0x20000
```

В ESP-IDF PowerShell замените `$IDF_PATH` на `$env:IDF_PATH` в этих двух командах. Для каждого дополнительного Node преобразуйте его собственный CSV. Размер раздела — **0x20000 (128 KiB)**, адрес — **0x9000**; они соответствуют таблицам разделов этого проекта.

## 7. Запишите NVS на соответствующую новую плату

Закройте monitor. Сверьте имя файла, модель и порт перед каждой командой:

```sh
python -m esptool --chip esp32s3 --port PORT_S3 write_flash 0x9000 secrets/bench-01/hub.nvs.bin
python -m esptool --chip esp32c3 --port PORT_C3 write_flash 0x9000 secrets/bench-01/node-0.nvs.bin
```

Не используйте `erase_flash`. Не записывайте файл Hub на C3 или один и тот же Node-файл на несколько плат. Если esptool не перезагрузил плату, нажмите RESET. Для дальнейшей работы обеим платам нужно питание, но USB к компьютеру достаточно оставить на диагностируемой плате.

## 8. Откройте веб-интерфейс

1. В monitor Hub проверьте строку `Web: https://192.168.4.1`.
2. На компьютере или телефоне подключитесь к Wi-Fi **SmartPlantOS** с `wifi_password` из `secrets/bench-01/access.json`. Останьтесь в этой сети, даже если ОС сообщает «без интернета».
3. Откройте **https://192.168.4.1**. Сертификат локальный, самоподписанный. В сведениях о сертификате сверяйте SHA-256 с `certificate_sha256` из своего файла настройки, затем разрешите доступ именно к этому Hub. Не отключайте проверку сертификатов во всём браузере. Если браузер запрещает исключение, импортируйте свой `hub-cert.pem` через настройки доверия ОС/браузера.
4. Введите `admin_password` из `access.json`. Сессия живёт 15 минут и хранится только в памяти страницы; перезагрузка страницы требует нового входа. Новый вход заменяет предыдущую сессию.
5. Синхронизируйте время кнопкой, дождитесь обновления списка и откройте растение. Конфигурация запрашивается у C3, а не подменяется демонстрационными числами.

`web/index.html` остаётся дизайн-прототипом с демонстрационными данными. На Hub встроен **`web/live.html`** — отдельный минимальный стендовый интерфейс. Он не требует интернета, CDN, облака или сервера на ПК. Совмещение его функциональности со всем дизайном прототипа — следующий UI-этап, а не уже готовая возможность.

При тайм-ауте команды используйте «Проверить последнюю команду» или остановку. Не создавайте новый полив просто потому, что ответ потерялся. Неизвестный результат не означает, что насос не включился.

## 9. Проверьте стенд без нагрузки

- После настройки обе платы загружаются без `LOCKED`, растение появляется online. Разрешите до 15 секунд на первые пакеты и обновление страницы.
- Без GPIO почва/бак не должны показывать выдуманные исправные измерения, а полив должен быть отклонён. Не пытайтесь обходить блокировку ради зелёного индикатора.
- Отключите питание Node: примерно через 15 секунд без телеметрии Hub считает его offline, интерфейс показывает отсутствие связи. Верните питание и дождитесь восстановления.
- На Node и Hub доступна команда `status` в monitor. Для разбора строк CBOR используйте `python tools/spp_inspect.py HEX`.
- После reboot Node сначала запрещает полив до времени от Hub. После reboot Hub синхронизируйте время заново.

Подключение датчика, поплавка и внешнего драйвера насоса — отдельный стендовый этап из [FIRMWARE.md](FIRMWARE.md). `--pins SOIL,TANK,PUMP` назначает **проверенные вами** выводы при создании первоначального комплекта настроек. У действующей установки пока нет безопасного инструмента смены GPIO и веб-секретов с сохранением остального NVS: не делайте это восстановлением старого дампа. До тестов питания, защиты, калибровки и отключения насоса не оставляйте полив без наблюдения.

## 10. Как обновлять код, не стирая настройки

Сохраните свои изменения, обновите нужную ветку через Git и откройте ESP-IDF терминал. Насос на время обновления отключите. Для каждого проекта:

```sh
cd firmware/node
idf.py build
idf.py -p PORT_C3 flash monitor
```

Затем аналогично в `firmware/hub` с `PORT_S3`. **Не повторяйте запись `*.nvs.bin`, provisioning и `erase_flash`**. Обычный `idf.py flash` обновляет bootloader, таблицу разделов и приложение, сохраняя NVS при неизменной разметке. Перед обновлением проверьте примечания версии: изменение разметки или формата safety требует отдельной миграции. После загрузки снова проверьте status, связь, время и настройки.

## Если что-то не получается

| Симптом | Что проверить |
|---|---|
| `idf.py` не найден | Открыт ли ESP-IDF терминал / выполнен ли `export.sh` |
| Порта нет | Кабель с данными, другой USB-разъём, native USB, список портов до/после подключения |
| `Failed to connect` | Закрыть monitor; удерживать BOOT, кратко нажать RESET, отпустить BOOT, повторить запись; при необходимости `-b 115200` |
| `Permission denied` на Linux | Права вашей учётной записи на serial-порт (обычно группа `dialout`), повторный вход после изменения группы |
| Неверный chip или размер flash | Сверить плату и проект; не игнорировать проверку и не добавлять `--force` |
| Ошибка PSRAM на S3 | Действительно ли это N16R8 с octal PSRAM; питание; настройки и ревизия платы |
| `LOCKED` после настройки | Роль, адрес NVS, собственный файл и целостность данных; не стирать NVS как «исправление» |
| Wi-Fi есть, HTTPS не запускается | Создан ли комплект с `--web`, есть ли сертификат и ключ; смотреть monitor Hub |
| Node offline | Питание, правильные STA MAC, общий канал/страна, ключи из одного комплекта |
| HTTP 401 / 429 | Сессия истекла / превышены пять входов за минуту; новый вход / подождать минуту |
| `clock_jump` | Часы ПК изменились более чем на 5 секунд относительно Hub; проверить часы, перезапустить Hub и синхронизировать; Node сохраняет свои защиты |
| `request_outcome_unknown` | Проверить исходный ID команды; не повторять Water с новым ID |

В отчёте об ошибке укажите commit, модель и маркировку платы, версию ESP-IDF, ОС, шаг и короткий лог без ключей. Отдельно отметьте, был ли подключён насос и какие GPIO использовались.
