# ADR-0018: два OTA-слота и подтверждённое обновление
Статус: Принято
Дата: 2026-11-02

## Контекст

Factory-разметка не оставляла места для отката. Обновление по USB с заменой единственного приложения не подходит для веб-установки. У C3 нет собственного Wi-Fi/HTTPS приложения, а Hub не должен считать подтверждение ESP-NOW подтверждением работоспособности новой версии.

## Решение

Профиль ota-v1: два одинаковых app-раздела, штатный ESP-IDF rollback, отдельная otadata и неизменные адреса NVS/PHY. Hub принимает файл порциями в неактивный слот либо во flash staging для C3. Образ проверяется по SHA-256, заголовку ESP, chip ID, flash size, имени проекта, версии и data ABI. Совместимые версии имеют суффикс -abi1; более старые версии отклоняются. SHA-256 не является подписью производителя. Пока нет Secure Boot и подписанных релизов, владелец выбирает доверенный файл самостоятельно.

C3 получает образ через SPU1: AES-GCM, ключ HKDF в отдельном от SPP домене, те же сохраняемые boot epochs и общий монотонный счётчик передачи. Передача stop-and-wait, ограниченные повторы, подтверждение смещения приложением, проверка повтора по flash. Транспорт не меняет локальные лимиты и запрещает старт при активном/незавершённом поливе или включённой автоматике.

Сначала проверяется весь образ, затем сохраняется идентичность операции и адрес выбранного слота, затем меняется boot partition. Новая версия проверяет запуск 30 секунд. Независимый таймер перезапустит её через 90 секунд без подтверждения, после чего штатный загрузчик выполнит rollback. Для C3 требуется восстановленная защищённая связь с Hub; для Hub — успешно поднятые обязательные локальные службы. Сравнение версий или наличие HELLO само по себе не означает успешное обновление. Подтверждение C3 проверяет новый boot epoch, идентичность операции, валидность и фактически запущенный слот.

Старые устройства переходят по USB: прежнее приложение остаётся ota_0, новое сначала записывается в ota_1, затем меняются загрузчик, таблица и otadata. NVS не читается в публичный пакет, не стирается и не заменяется резервной копией. Прерывание питания при записи загрузчика/таблицы требует USB-восстановления; эту короткую миграцию нельзя назвать атомарной. Последующие обновления не меняют разметку.

## Последствия

В каждой плате резервируется место под второй образ. Hub дополнительно хранит один образ C3 во flash. Одновременно выполняется только одна операция обслуживания. Продолжение передачи после перезапуска Hub не обещается: старый образ C3 остаётся загрузочным до успешной финальной проверки, незавершённая сессия закрывается по тайм-ауту. Данные ABI меняются только отдельной миграцией с новой ADR и правилами обратной совместимости.

## Что не проверено

Результаты host/SDK/стендовых проверок публикуются отдельно. Обрыв питания в произвольный момент записи, старение flash, работа под нагрузкой и подписанные производственные релизы требуют дополнительных испытаний.
