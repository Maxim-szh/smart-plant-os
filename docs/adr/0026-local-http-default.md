# ADR-0026: HTTP по умолчанию в локальной сети
Статус: Принято
Дата: 2026-11-14

## Контекст

Самоподписанный HTTPS требует ручного доверия на каждом клиенте. Для домашнего
Hub это мешает первому подключению. Пользователь выбрал локальный HTTP по умолчанию.

## Решение

Новые сборки S3 включают CONFIG_SP_WEB_LOCAL_HTTP. Один сервер работает на порту
80; отключение опции возвращает HTTPS на 443. Это уточняет транспорт и cookie
из ADR-0016; прежние ограничения авторизации сохраняются. HTTP-cookie называется
sp_http_session, HTTPS-cookie — sp_session. Обе HttpOnly/SameSite=Strict;
Secure применяется только с HTTPS. Проверка Origin учитывает выбранную схему.

Ключи, NVS и связи C3 не меняются. Мастер использует текущую схему страницы.
Hub проверяет SHA-256 образа перед переключением OTA-раздела независимо от
наличия SubtleCrypto в браузере. Дайджест не заменяет подпись издателя.

## Последствия

HTTP не защищает ключ и сеансы от перехвата в сети. Это осознанный выбор для
доверенной домашней сети, без публикации Hub в Интернет. HTTPS остаётся опцией.
Старый sdkconfig требует явного изменения настройки, старый HTTPS-ярлык — замены.
HTTP не является secure context: нельзя обещать Service Worker, офлайн-режим
или одинаковую установку PWA во всех браузерах. Первоначальное создание комплекта
по-прежнему включает сертификат для возможности возврата к HTTPS.

## Что не проверено

Открытие растений по HTTP подтверждено на S3 N8R2 и iPhone. Иконка нового ярлыка,
поведение установленного приложения на всех версиях iOS/Android и аппаратный
возврат с HTTP на HTTPS отдельно не проверены. Результаты: [стенд](../bench/2026-11-14-local-http-pwa.md).
