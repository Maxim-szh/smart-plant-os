# ADR-0005: Время и поведение после перезагрузки

Статус: Принято
Дата: 2026-10-24

## Контекст

У Node и Hub нет часов реального времени. Календарное время нужно для суточного лимита. В режиме Standalone нет интернета и NTP: единственный источник времени — браузер пользователя. Если время можно переставить назад, суточный лимит можно незаметно сбросить.

## Решение

1. **Правило из [WATERING.md](../WATERING.md) сохраняется без ослаблений.** Без достоверного календарного времени (`clock_state: unset`) запуск любого полива блокируется, причина `clock_unset`. Это относится и к ручному поливу.
2. Для максимальной длительности насоса и паузы между поливами используется монотонный таймер. Он не зависит от календарного времени.
3. Источники календарного времени у Hub: NTP (если доступен), браузер пользователя с явным подтверждением, ручной ввод. Hub сообщает узлу время вместе с качеством источника.
4. Node принимает время только от аутентифицированного Hub. Дальнейшие синхронизации не должны незаметно переводить время назад: существенная поправка фиксируется событием и не уменьшает уже учтённый расход за сутки. Допуск и поведение при поправках определяются в этапе B и проверяются тестами.
5. После перезагрузки Node без достоверного времени автополив остаётся заблокированным до получения времени от Hub. После восстановления связи Node сообщает причину отказа.
6. **Режим «ограниченного автономного полива после перезагрузки» не вводится.** Он выносится в отдельный ADR после стендовых проверок: потребуется оценить сохранение журнала расхода, износ flash и поведение при долгом отключении питания.

## Последствия

- Если Hub и питание узла пропали одновременно, автополив возобновится только после получения времени. Это безопасно, но для долгого отсутствия пользователя это ограничение автономности. Оно записано как известное.
- Интерфейс Hub должен предлагать выставить время при первом запуске в Standalone.

## Что не проверено

Допуск поправок времени, формат и ресурс записи журнала расхода, пережитие суточного счётчика через перезагрузку на реальной flash не определены и не проверены.
