# ADR-0003: Сериализация SPP — CBOR с числовыми ключами

Статус: Принято
Дата: 2026-10-24

## Контекст

Кадр ESP-NOW v1.0 вмещает 250 байт полезных данных. В эти 250 байт входят и заголовок SPP, номер сообщения, тег аутентификации. Размеры документов из `spec/v1`, измеренные 2026-10-24 на примерах репозитория (в байтах):

| Документ | JSON компактный | CBOR, ключи-строки | CBOR, числовые ключи |
|---|---|---|---|
| `State` | 678 | 564 | 287 |
| `Config` | 430 | 372 | 163 |
| `CommandResult` | 269 | 236 | 145 |
| `EventPage` (4 события) | 977 | 815 | 529 |
| запрос полива | 90 | 81 | 47 |
| запрос остановки | 131 | 122 | 83 |

Числовые ключи в этой оценке присвоены автоматически, это нижняя граница. Заголовок и тег в таблицу не входят.

## Решение

1. На радио используется **CBOR (RFC 8949) с числовыми ключами**. Таблица «число → имя поля» входит в спецификацию SPP и в тестовые векторы.
2. JSON остаётся форматом REST API Hub, спецификации `spec/v1` и человекочитаемых примеров. Тестовые векторы SPP хранятся парой: JSON-представление и CBOR в шестнадцатеричном виде.
3. SPP не пересылает документы `spec/v1` целиком. Узел отправляет компактные сообщения (показания, результат команды, события), а Hub собирает из них `State`, `EventPage` и `Registry`.
4. Целевой размер сообщения SPP вместе с заголовком и тегом — не более 200 байт. Сообщения, которые не помещаются (например, полная `Config`), разделяются по полям или фрагментируются; фрагментация вводится только при доказанной необходимости.
5. Отвергнуто: JSON на радио (`State` не помещается ни в какой форме); собственный бинарный формат (дорого поддерживать, нет инструментов); CBOR со строковыми ключами (`State` 564 байта).
6. Библиотека CBOR выбирается в этапе B по размеру, лицензии, отсутствию динамической памяти и возможности собирать на хосте.

## Последствия

- Сообщения SPP придётся проектировать как маленькие, а не как слепок REST.
- Для проверки и отладки нужен инструмент, переводящий CBOR в JSON и обратно по таблице ключей.

## Что не проверено

Конкретная библиотека CBOR для ESP-IDF не выбрана и не проверена. Накладные расходы заголовка и аутентификации зависят от этапа B.
