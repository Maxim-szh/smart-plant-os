# ADR-0004: Первичная привязка и ключи

Статус: Предложено
Дата: 2026-10-24

## Контекст

Команда насосу — физическое действие, анонимный клиент не должен её отправить. По документации Espressif LMK шифрует кадры пары, а шифрование multicast не поддерживается; шифрование broadcast в документации не описано. Поэтому поиск устройств и привязка идут по каналу, который считается открытым и неаутентифицированным. Шифрование канала не заменяет защищённую процедуру привязки (см. [NETWORK.md](../NETWORK.md)).

## Решение (направление)

Процедура пользователя:

1. Пользователь включает новый Node. Непривязанный Node не принимает команд, не включает насос и отвечает только на запросы привязки.
2. Пользователь открывает интерфейс Hub и запускает поиск. Hub открывает окно привязки ограниченной длительности.
3. Привязка подтверждается **физически**: нажатием кнопки на Node, если на выбранной ревизии платы есть доступная кнопка; иначе — одноразовым кодом привязки, который Node выдаёт только на физический USB-доступ специальной командой и никогда не пишет в обычный журнал.
4. Hub и Node выполняют аутентифицированный обмен ключами (кандидат: X25519 с проверкой подтверждения общим секретом привязки) и выводят ключи через HKDF с раздельным контекстом.
5. Node сохраняет идентификатор Hub и ключи; Hub сохраняет ключи узла в защищённом разделе хранилища.
6. Пользователь назначает растение и выполняет калибровку.

Иерархия ключей:

- ключ уровня прикладной аутентификации SPP (AEAD), отдельный для каждой пары;
- LMK ESP-NOW для каждой пары выводится отдельно и не используется как единственная защита;
- PMK задаётся Hub и передаётся при привязке;
- счётчики сообщений сохраняются так, чтобы после перезагрузки не повторялся номер при том же ключе.

Дополнительно: привязку можно удалить с Hub и сбросить на Node (кнопкой или USB); после сброса ключи стираются, `device_id` сохраняется. Секреты не записываются в журналы, `GET /config` их не возвращает, в Git их нет.

## Последствия

- Кнопка или USB-команда становятся частью требований к плате узла.
- Криптографическая часть пишется один раз и тестируется на хосте векторами.

## Что не проверено

Решение остаётся предложением, пока не подтверждено: есть ли кнопка и светодиод, доступные программно, на конкретной ревизии ESP32-C3 Super Mini; какие криптопримитивы (X25519, HKDF, AEAD) включены в выбранную версию ESP-IDF и сколько они занимают; сколько памяти и flash требуют зашифрованные пиры на Hub (по документации их до 17, по умолчанию 7, для 10 узлов значение надо увеличить). Стойкость процедуры не оценивалась независимо.
