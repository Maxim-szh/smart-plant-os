# ADR-0009: Доступ браузера к Hub

Статус: Предложено
Дата: 2026-10-24

## Контекст

REST API Hub принимает команды полива и изменение защитных настроек. Анонимный доступ из локальной сети недопустим. В режиме Standalone доверенного сертификата нет, в Home Network HTTPS на Hub возможен, но способ выдачи сертификата, с которым браузеры не показывают предупреждение, не определён. Прежнее решение «HTTPS на узле с закреплением сертификата в координаторе» относилось к API на узле и больше не применяется напрямую (см. [SECURITY.md](../SECURITY.md)).

## Решение (минимальные требования)

1. Изменяющие маршруты требуют аутентификации; чтение состояния без авторизации допускается только при явном включении пользователем.
2. Первый вход создаёт административный секрет при физическом доступе к Hub (например, одноразовый код через USB-консоль или физическая кнопка), а не публичный пароль по умолчанию.
3. Сессии ограниченной длительности, защита от межсайтовых запросов, ограничение частоты команд и попыток входа.
4. Каждая команда полива имеет `command_id` и срок действия; повтор не запускает насос.
5. Изменение защитных настроек (максимальное время насоса, порция, суточный лимит, интервал) требует явного подтверждения пользователя в интерфейсе. ИИ и интеграции могут только предлагать изменения.
6. Журнал фиксирует авторизованные действия без секретов.

Способ транспорта (HTTP внутри пароля точки доступа, HTTPS с закреплением сертификата или собственный центр сертификации) выбирается в этапе D после измерения памяти Hub.

## Последствия

- Первый запуск потребует физического действия.
- Ответственность за безопасность браузерной части лежит на Hub, а не на узлах.

## Что не проверено

Ни один из вариантов не реализован и не измерялся. Память S3 для TLS вместе с точкой доступа и ESP-NOW не измерена. Удобство первого запуска не оценивалось.
