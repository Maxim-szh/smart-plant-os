# ADR-0006: Сетевые режимы Hub — Standalone и Home Network

Статус: Принято
Дата: 2026-10-24

## Контекст

ESP-NOW работает на радиоканале устройства: по документации канал пира должен совпадать с текущим каналом или быть равен 0 (текущий), иначе отправка возвращает ошибку. Когда Hub подключён к роутеру, канал определяет роутер и он может измениться. Документация Wi-Fi, прочитанная при аудите, не описывает совмещение AP и STA, правила выбора канала и поведение при смене канала роутера, поэтому они считаются непроверенными. Подробнее — [NETWORK.md](../NETWORK.md).

## Решение

1. **Standalone — основной режим MVP.** Hub создаёт собственную точку доступа на фиксированном канале, который задаёт пользователь (по умолчанию выбирается при первом запуске). ESP-NOW работает на том же канале. Интернет и роутер не нужны.
2. **Home Network — этап F.** Hub подключается к домашней сети и отдаёт интерфейс в LAN. Канал определяется роутером, на него переходят и узлы.
3. Для Home Network закладывается механизм обнаружения смены канала: Hub сообщает узлам плановый переход, а узел, потерявший Hub, выполняет ограниченный по частоте поиск по разрешённым каналам, отправляя аутентифицированный запрос. Во время поиска Node остаётся автономным. Это проект механизма, а не реализованная функция.
4. Переход между режимами выполняется как плановая операция смены канала с подтверждением пользователя и проверкой связи с каждым узлом. **Бесшовное переключение не обещается** до реализации и испытаний.
5. Набор допустимых каналов зависит от кода страны, его нужно задавать явно.

## Последствия

- MVP не зависит от поведения домашнего роутера.
- Home Network откладывается до измерений на стенде, а не обещается заранее.

## Что не проверено

Совмещение STA и SoftAP на S3, число клиентов SoftAP, время и надёжность перехода на новый канал, поведение при отключении роутера, потребление памяти при одновременной работе HTTP-сервера, точки доступа и 10 зашифрованных пиров ESP-NOW.
