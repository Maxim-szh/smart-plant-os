# ADR-0006: Сетевые режимы Hub — Standalone и Home Network

Статус: Принято
Дата: 2026-10-30

## Контекст

ESP-NOW работает на радиоканале устройства: по документации канал пира должен совпадать с текущим каналом или быть равен 0 (текущий), иначе отправка возвращает ошибку. Когда Hub подключён к роутеру, канал определяет роутер и он может измениться. Документация Wi-Fi, прочитанная при аудите, не описывает совмещение AP и STA, правила выбора канала и поведение при смене канала роутера, поэтому они считаются непроверенными. Подробнее — [NETWORK.md](../NETWORK.md).

## Решение

1. Hub всегда поднимает собственную защищённую точку доступа на заданном канале. Она даёт локальный путь настройки и управления без роутера.
2. Установщик может записать домашние Wi-Fi credentials в Hub. Для стендовой совместимости пользователь закрепляет канал роутера 2,4 ГГц и задаёт тот же канал Hub/ESP-NOW. C3 остаются на ESP-NOW и не ассоциируются с роутером.
3. Если Hub не подключился к роутеру или обнаружил другой канал, он отключает STA и продолжает standalone на заданном канале. Пользователь получает диагностику через USB; Node не теряет свой радиоканал.
4. Автоматическое обнаружение и смена канала, изменение сетевых credentials из UI и бесшовный roaming не реализованы и не обещаются до испытаний.
5. Набор допустимых каналов зависит от кода страны. Текущий установщик ограничен каналами 1–11; пользователь обязан соблюдать местные требования радиочастот.

## Последствия

- MVP не зависит от поведения домашнего роутера.
- Одновременная AP+STA и ESP-NOW работа требует длительных измерений на физических S3 и C3.
- TLS-сертификат пока предназначен для адреса точки доступа; локальный доступ к веб-панели через DHCP-адрес требует отдельного решения.

## Что не проверено

Совмещение STA и SoftAP на S3, число клиентов SoftAP, время и надёжность перехода на новый канал, поведение при отключении роутера, потребление памяти при одновременной работе HTTP-сервера, точки доступа и 10 зашифрованных пиров ESP-NOW.
