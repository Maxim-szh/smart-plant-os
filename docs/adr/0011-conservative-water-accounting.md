# ADR-0011: Консервативный учёт воды при сбоях и перезапусках

Статус: Принято
Дата: 2026-10-25

## Контекст

Нет расходомера и независимых часов. При отключении питания неизвестно, сколько воды успел подать насос. Нельзя освобождать лимит только из-за нового времени от Hub или окончания календарного дня.

## Решение

Перед включением Node резервирует полную порцию, сохраняет команду, cooldown и событие одним NVS commit. Остановка до конца не уменьшает резерв. Для освобождения записи должны пройти 24 h по UTC и монотонному времени текущего запуска; для записи предыдущего запуска — минимум 24 h с reboot. Команды без UTC удерживаются по монотонному окну до появления времени. Разрешение очередной порции учитывает этот резерв и `max_daily_ml`, поэтому оно не слабее календарного дневного лимита.

После reboot cooldown не короче полного настроенного интервала плюс максимальные 30 s работы насоса; если сохранённый календарный cooldown длиннее, используется он. Неоконченная команда становится failed и требует физического осмотра/снятия защёлки. Подтверждение неисправности не сбрасывает бюджет, cooldown или UUID команд.

`daily_estimated_ml` публичного API сохраняет прежний смысл оценочного дневного объёма. Дополнительное необязательное `safety_reserved_ml` обозначает именно защитный резерв. SPP поле 16 передаёт резерв, его нельзя молча отобразить как фактически поданную воду. Отдельный расчёт календарного дневного объёма должен появиться в REST-адаптере; сейчас HTTP не реализован.

## Последствия

Перезапуск может задержать следующий полив даже при старых командах. Это допустимый консервативный компромисс начального профиля. Не следует перезапускать плату для обхода защит. Для менее консервативного поведения нужны надёжное время и отдельное доказательство сохранения лимитов.

## Что не проверено

Реальное отключение питания во время NVS commit, ресурс flash и пригодность выбранного режима резервирования для конкретных растений. Логические сценарии проверяются на хосте; аппаратные должны войти в протокол стенда.
