# ADR-0007: Интерфейс хранилища истории и microSD

Статус: Принято
Дата: 2026-10-24

## Контекст

Долгая история хранится на Hub. Предполагаемая карта — 2–4 ГБ. История нужна для просмотра и анализа, но не участвует в решении о поливе. Подробную реализацию (формат файлов, индексы, восстановление после сбоя, ресурс карты) откладываем.

## Решение

1. Hub пишет историю через узкий интерфейс хранилища: добавить запись; прочитать записи после курсора с лимитом; получить границы и состояние хранилища.
2. Запись содержит идентификатор события (`<device_id>:<seq>` из [PROTOCOL.md](../PROTOCOL.md)), `device_id`, `seq`, календарное время или `null`, `uptime_ms`, признак качества данных и тело события. Различие между текущим и последним известным значением определяется возрастом и качеством, а не самим хранилищем.
3. Формат экспорта — JSON Lines: один объект `Event` из `spec/v1` на строку, плюс необязательные служебные поля Hub в отдельном объекте.
4. Реализация по умолчанию — ограниченный кольцевой буфер в памяти Hub. Реализация на microSD подключается позже за тем же интерфейсом.
5. Отсутствие или отказ карты не останавливает работу: Hub показывает состояние «история недоступна», команды и показания продолжают работать.
6. Node хранит только короткий ограниченный журнал и минимальное состояние. История не хранится у узла как единственная копия.

## Последствия

- Интерфейс можно тестировать на хосте с имитацией хранилища, включая отказ.
- Подсистема microSD не блокирует остальные этапы.

## Что не проверено

Подключение карты к конкретной плате S3 N16R8 (интерфейс, выводы, питание) и износ при выбранной частоте записи.
