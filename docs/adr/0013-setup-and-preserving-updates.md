# ADR-0013: Веб-настройка и обновления с сохранением установки
Статус: Принято
Дата: 2026-11-02

## Контекст

Первоначальная установка и обновление сейчас смешиваются. Повторная запись полного NVS меняет ключи, epochs и защитные лимиты. Пользователю нужен первый запуск Hub без подключённых C3, настройка домашней сети через AP и добавление растений позднее. Factory-разметка действующих плат не имеет OTA-слотов.

## Решение

- USB-обновление записывает только приложение, проверяет тип чипа, установленную таблицу разделов и размеры. Оно не записывает NVS, загрузчик или таблицу разделов. Первая установка явно отделена от обновления.
- Сетевые требования ADR-0006 уточняются: AP+STA и ESP-NOW используют общий текущий канал 1–11; паспорт Hub сообщает реальный канал. C3 перебирает разрешённые каналы после потери связи и фиксирует связь только после аутентифицированного обмена со своим Hub.
- Hub допускает ноль привязанных устройств. `/setup` обслуживается самим Hub; API настройки требует существующую HTTPS-сессию и same-origin проверку. Пароли не возвращаются API.
- Подключение к домашней сети выполняется асинхронно в application task. Новые credentials сохраняются только после получения IP; при тайм-ауте возвращается прежняя конфигурация. AP остаётся доступной. Операции настройки выполняются по одной.
- Первоначальная привязка C3 использует физический USB и приватный файл передачи ключей. Web экспортирует публичный паспорт Hub; программа генерирует индивидуальные случайные LMK/app keys, записывает их только в новый пустой NVS C3 и сохраняет файл привязки с ограниченными правами. Авторизованный владелец импортирует его на Hub через HTTPS. Это USB-assisted onboarding, не реализованный радиопоиск из ADR-0004.
- Реестр дополнительных связей хранится отдельным атомарным blob. Существующая связь не заменяется импортом другого ключа. Safety blob и replay epochs не обнуляются.
- Web OTA остаётся следующим этапом: необходимы два app-слота, otadata, проверка образа, откат и отдельная миграция factory-разметки. Кнопка USB-обновления не изображается работающим web OTA.

## Последствия

Первый запуск начинается с Hub; C3 добавляются позже без переустановки всей системы. Файл привязки содержит секреты и даёт доступ к конкретному C3, его нельзя публиковать. Ключи защищены от передачи открытым радиоканалом, но физическое чтение flash без NVS encryption пока возможно.

## Что не проверено

Длительные AP+STA+ESP-NOW испытания, переключение канала на разных роутерах, обрыв питания при commit и установка на всех ревизиях плат требуют стенда. USB-assisted схема требует проверки обеих плат. OTA и полностью беспроводная привязка не реализованы этим ADR.
