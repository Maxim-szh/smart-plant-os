# ADR-0023: комнаты, видимый дневник и обслуживание
Статус: Принято
Дата: 2026-11-05

## Контекст

Дневник трудно найти, добавление нескольких устройств повторяет длинный редактор, а плоская полка плохо показывает растения из разных комнат. Для обслуживания требуется подтверждённое отключение автоматического режима, которое не должно внезапно отменяться после перезапуска Hub.

## Решение

[Домашний интерфейс](../UX-HOME.md) сохраняет палитру, SVG и семейства шрифтов. Дневник — самостоятельный раздел навигации и действие карточки. Группы используют room метаданных; перенос защищён revision, фильтр/порядок/свёрнутость — настройки конкретного браузера. Краткий мастер описывает растение после online и предлагает добавить следующее; setup_stage не выдаёт оборудование за настроенное.

[Контракт experience/v1](../../spec/experience/v1/README.md) добавляет общий GET дневника без нового формата записей. Ручной полив — заметка владельца, не команда и не обход учёта воды.

Обслуживание хранит отдельное намерение Hub и отключает automatic обычным CONFIG с CAS Node. Сначала commit намерения, затем отправка; active только после достоверного ручного режима. При обрыве/перезапуске состояние pending/unverified, без фонового повторения POST. Коррекция в интерфейсе не включает насос. Пока намерение существует, API не позволяет включить automatic другим редактором. finish снимает только отметку, оставляя manual. Автоматического возобновления по времени нет. Safety ABI, replay и SPP не меняются.

Шрифты Onest/Literata с кириллицей встроены в Hub, OFL лицензии приложены. Они не требуют внешнего сайта при загрузке интерфейса. C3 не получает изображения, шрифты и новые HTTP-ресурсы.

## Последствия

Вход в обслуживание требует чтения CONFIG и ответа контроллера. Если Hub пропал до отправки, C3 мог остаться в прежнем автоматическом режиме — UI не имеет права показывать подтверждённую паузу. При неизвестном результате владелец сначала проверяет состояние. Отметка привязана к plant UUID и устройству, не наследуется другой привязкой. Ошибки NVS не исправляются стиранием.

Локальные быстрые записи не корректируют cooldown/суточные лимиты Node. UI сообщает это до сохранения. Агрегированный дневник ограничен существующими 64 записями; чтение не пишет flash. Большие изображения концепта не встраиваются в прошивку; существующие SVG остаются рабочими активами.

## Что не проверено

Полив с физическими нагрузками, реальные датчики и длительный ресурс flash ещё не испытаны. Установка на S3 проверяется отдельно в отчёте стенда; перенос mock-сценариев не означает физической проверки C3. При принудительном закрытии мобильного браузера сохранность несохранённого черновика не гарантируется. Срок обслуживания не хранится и не обещается.
