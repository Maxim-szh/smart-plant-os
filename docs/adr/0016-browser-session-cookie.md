# ADR-0016: короткий сеанс владельца в браузере
Статус: Принято
Дата: 2026-11-02

## Контекст

После первичной настройки пользователь открывает приложение в домашней сети и добавляет растения там. Сеанс, существующий только в JS одной страницы, теряется при переходе между настройками и приложением. Хранение ключа администратора в localStorage для этого не требуется и не допускается.

## Решение

Успешный POST /api/v1/session сохраняет прежний JSON с Bearer token и дополнительно устанавливает cookie sp_session с тем же случайным токеном: Path=/; Max-Age=900; HttpOnly; Secure; SameSite=Strict. Серверная проверка срока остаётся обязательной. API принимает текущий Bearer или эту cookie; проверка Origin, Content-Type и лимиты входа сохраняются. DELETE сеанса инвалидирует серверный токен и удаляет cookie. Значение ключа администратора нигде в браузерном хранилище не сохраняется. Токен не публикуется в URL.

Приложение может восстановить реестр растений через same-origin GET nodes. Без сеанса оно показывает макет, а вход предлагает только при действии владельца. Состояние реальных растений обновляется отдельно и не подменяется демонстрационными данными. Истёкший сеанс делает отображённое состояние неподтверждённым.

## Последствия

Ключ не нужен повторно при переходе между страницами и перезагрузке в пределах 15-минутного сеанса одного HTTPS-origin. Для домашнего IP и IP точки доступа cookie разные: автоматического переноса секретов между origin нет. Перезапуск Hub прекращает сеанс, но не меняет ключ владельца. Инженерный сервер по-прежнему хранит один активный сеанс; полноценная модель нескольких пользователей и независимых сеансов не реализована.

## Что не проверено

Браузерные тесты проверяют HttpOnly-cookie и восстановление реестра при reload. Аппаратные результаты фиксируются отдельно в docs/bench. Разные версии мобильных браузеров и многопользовательский сценарий требуют отдельной проверки. Cookie не заменяет проверку сертификата и не делает self-signed HTTPS автоматически доверенным.
