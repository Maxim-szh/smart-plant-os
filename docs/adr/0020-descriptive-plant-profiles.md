# ADR-0020: вид, стадия и иллюстрация растения
Статус: Принято
Дата: 2026-11-03

## Контекст

Реальное приложение должно использовать визуальный язык примера и позволять выбирать вид и стадию без зависимости от наличия датчиков. Числовые ориентиры прежней draft knowledge base не являются проверенными настройками полива. Локальное хранилище браузера не подходит для общего профиля растения.

## Решение

Профиль хранится на Hub вместе с UUID, именем и комнатой. growth_stage — nullable, задаётся человеком; неизвестное значение не заменяется догадкой. Вид и стадия не меняют Config, калибровку, порцию, лимиты или команды Node. SPP и safety/state_v1 не меняются. Новый UI использует прежний SVG-рисунок, палитру и классы стадий. Числовые советы и прогнозы из demo не импортируются в реальный режим.

Единый справочник data/knowledge-base/profiles.json задаёт виды, группы, стадии и качественные памятки с первичными источниками. tools/generate_plant_profiles.py создаёт JS и C-маски допустимых стадий. Несоответствие сгенерированных файлов блокирует check. Неизвестный вид сохраняется и может иметь одну из общих ручных стадий. У известных видов проверяется соответствие стадии группе.

sp_plant_meta_t v3 добавляет строку стадии; legacy sp_plant_meta_v2_t сохраняет размер 228 bytes. catalog/state_v2 содержит каталог v2. При отсутствии нового ключа каталог v1 проверяется, копируется с пустыми стадиями и записывается одним commit. Ошибка миграции останавливает загрузку каталога; неверный новый blob не подменяется старым. Старые blobs не перезаписываются. Firmware до этой миграции видит свой старый снимок, а не последующие изменения нового каталога; откат старого UI не является способом редактировать новый профиль. Data ABI защиты остаётся 1.

PUT metadata использует существующую revision. Старый клиент, не передавший стадию, сохраняет её при неизменном виде и очищает при смене вида. Новое поле не заменяет setup_stage. Backup v2 включает growth_stage; импорт v1 сохраняет стадию существующей записи при прежнем виде. Импорт и новый профиль проверяются до commit.

HTTP принимает до 12288 bytes JSON и возвращает до 24576 bytes: границы учитывают 20 максимально экранированных имён/комнат и preview с прежними значениями. Буферы остаются ограниченными, приём HTTP выделяется на heap, а не на стек Node.

## Последствия

Имя, вид и стадия доступны всем браузерам после перезапуска Hub. Их можно менять при offline C3. Замена контроллера и backup не теряют стадию. Предпросмотр показывает описание будущей карточки, а не измерения датчика. Автоопределение стадии и автоматическое применение рекомендаций отсутствуют.

## Что не проверено

Не проверялись аппаратные датчики, полив, соответствие рисунка реальному растению и агрономическая точность автоматических режимов. Host/browser/SDK и проверка физического Hub фиксируются отдельно. Качественные памятки не заменяют подбор условий для конкретного сорта и субстрата.
