# ADR-0008: Интерфейс — адаптер данных, термины и пометки демонстрации

Статус: Принято
Дата: 2026-10-24

## Контекст

`web/index.html` — единый файл на чистом JS с демонстрационными массивами и глобальным состоянием. Дизайн нужно сохранить. Прототип сейчас показывает то, чего контракт не обещает: процент бака, «влажность почвы» вместо индекса, точный объём полива, одну плату с шестью растениями, GPIO, которых нет у C3.

## Решение

1. Дизайн, стиль, темы, адаптивность, мастера и страницы растений сохраняются. Файл не переписывается с нуля.
2. Сначала вводится **слой источника данных** с двумя реализациями: демонстрационной (нынешние массивы) и реальной (REST API Hub). Экраны обращаются к слою, а не к массивам.
3. Растение в интерфейсе соответствует одному Node. Модель «одна плата, шесть растений» остаётся только в демонстрационном источнике и помечена.
4. Интерфейс показывает только возможности, которые устройство объявило (`capabilities`).
5. Термины: вместо «влажность почвы» — **«индекс почвы»** с подсказкой, что это результат калибровки датчика в вашем субстрате, а не объёмная доля воды. Объём полива — **оценка** («≈150 мл»), пока нет расходомера. Бак без датчика уровня не показывается в процентах: только «вода есть / воды нет / неизвестно».
6. Демонстрационные данные помечаются видимой плашкой. GPIO, номера портов и значения диагностики из демонстрации не показываются как реальные.
7. «Умный» режим в интерфейсе сопровождается пометкой, что в v1 на насос влияют только ручной режим и порог (см. [WATERING.md](../WATERING.md)); стадия, сезон, статистика и ИИ пока дают рекомендации.
8. Для каждого экрана, затрагивающего данные устройства, существуют состояния «нет связи» и «команда отклонена с причиной».

## Последствия

- Часть красивых, но пока недостоверных элементов получает пометку, а не удаляется.
- Масштабный рефакторинг интерфейса откладывается, этап E подключает реальный источник.

## Что не проверено

Реальные API Hub ещё не существуют, поэтому реальный источник данных проверяется позже, на этапе E.
