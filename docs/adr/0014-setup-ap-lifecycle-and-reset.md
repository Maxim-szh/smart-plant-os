# ADR-0014: Жизненный цикл точки настройки и явный заводской сброс
Статус: Принято
Дата: 2026-11-02

## Контекст

Владелец выбрал постоянный пароль `smartplantos` вместо открытой AP и отключение точки после подключения к домашней сети. Требуется проверить новый первый запуск на обеих платах, сохранив безопасное разделение reset/update из ADR-0013.

## Решение

- SSID `SmartPlantOS`, WPA2-PSK, пароль `smartplantos`. Этот пароль публичный и не считается правом управления. Setup API по-прежнему требует индивидуальный ключ администратора и HTTPS.
- AP включена при старте настроенного Hub. После 30 s устойчивого домашнего Wi-Fi она выключается; STA и ESP-NOW продолжают работать. После 60 s непрерывной потери домашней сети AP включается вновь. При пробной настройке новой сети AP включается сразу.
- Физическая USB-команда `setup-ap` открывает окно восстановления на 5 минут с последующим обычным grace-периодом. Ключи, домашняя сеть и настройки при этом сохраняются. Без валидного provisioning AP не открывается.
- Политика времени вынесена в отдельное ядро `sp_ap_policy`; переключение Wi-Fi выполняет application task.
- `factory-reset` — отдельное действие USB-мастера. Проверяются чип/разметка/NVS; требуется ввод `RESET <MAC>`. Стирается только NVS 0x9000..0x28fff. Это уничтожает ключи, связи, настройки и лимиты; приложение сохраняется. После reset выполняется новая установка с полностью новыми ключами. Старые образы NVS не восстанавливаются.
- Первичная установка сохраняет публичный паспорт Hub рядом с access.json; новый C3 можно подготовить по USB до подключения Hub к роутеру.

## Последствия

Узнаваемый пароль AP упрощает первый вход, но не защищает от подключения постороннего клиента к радиосети. Управление остаётся за индивидуальной аутентификацией. При работе в домашней сети точка настройки обычно отсутствует. После reset прежние access-файлы недействительны; это не способ обновления прошивки.

## Что не проверено

До отдельной записи результатов: первый запуск обеих физических плат после reset, WPA2 join на телефоне, фактическое отключение AP и восстановление при длительном исчезновении роутера. Сценарии таймеров проверяются на хосте; аппаратный отчёт дополняется отдельно. Reset не тестируется с подключёнными исполнительными устройствами.
