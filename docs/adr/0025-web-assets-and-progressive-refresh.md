# ADR-0025: Сжатые ресурсы и раннее отображение сада
Статус: Принято
Дата: 2026-11-06

## Контекст

Статика передавалась без сжатия с no-store, а начальный экран ожидал последовательного опроса всех контроллеров. Фоновое обновление пересоздавало DOM даже без изменения содержимого.

## Решение

[Правила производительности](../WEB-PERFORMANCE.md): детерминированный gzip при сборке, отдельные ETag вариантов и обязательная ревалидация статики, ранний показ каталога и выбранного растения, объединение только выполняющихся GET с независимыми объектами ответа, сохранение стабильного DOM. Лимиты HTTP/радио не увеличиваются.

## Последствия

Flash содержит исходные и сжатые варианты; расход RAM на компрессию отсутствует. У каждого изменённого файла новый ETag, поэтому OTA не требует ручной очистки кеша. API остаётся no-store; сессионные данные и команды не кешируются. Небольшая разница времени между состояниями растений явно сохраняется, а не маскируется единой фиктивной меткой.

## Что не проверено

Ускорение зависит от устройства, браузера и сети. Тест с задержанными ответами проверяет порядок отображения, не подменяет измерение HTTPS на S3. Длительная работа десяти реальных C3 требует отдельного стенда. Публичные API, safety и калибровка этим решением не расширяются.
