# Сеть: ESP-NOW и режимы Hub

Это проектный документ. Реализации и стендовых испытаний нет. Факты об ESP-NOW взяты из документации Espressif (страницы ESP-NOW для ESP32-S3 и ESP32-C3, ESP-IDF 6.1, и руководство Wi-Fi), прочитанной 2026-10-24. Если в документации чего-то нет, это записано как «не подтверждено», а не угадано. Решения: [ADR-0002](adr/0002-transport-espnow-and-spp.md), [ADR-0006](adr/0006-network-modes.md).

## Что подтверждено документацией

| Факт | Значение |
|---|---|
| Размер полезных данных | до 250 байт (v1.0) и до 1470 байт (v2.0) |
| Совместимость версий | получатель v2.0 принимает v1.0 и v2.0; получатель v1.0 принимает пакеты v2.0 только до 250 байт |
| Число пиров | всего до 20 |
| Зашифрованные пиры | до 17, по умолчанию 7; задаётся параметром `CONFIG_ESP_WIFI_ESPNOW_MAX_ENCRYPT_NUM` |
| Ключи | PMK и LMK по 16 байт; без LMK кадры пары не шифруются |
| Шифрование | шифрование multicast не поддерживается; про broadcast в документации не сказано |
| Канал | канал пира равен 0 (текущий) или совпадает с каналом устройства, иначе ошибка отправки |
| Интерфейсы | отправка возможна через STA и SoftAP, интерфейс должен быть включён до отправки |
| Порядок запуска | Wi-Fi запускается до `esp_now_init()`, ESP-NOW останавливается до остановки Wi-Fi |
| Колбэки | вызываются из высокоприоритетной задачи Wi-Fi; тяжёлую работу в них делать нельзя, данные передаются в очередь |
| Результат отправки | «успех» означает приём на уровне MAC, а не доставку приложению |
| Подтверждения и повторы | встроенных механизмов на уровне приложения нет, их делает приложение |
| Последовательность отправки | при слишком частой отправке порядок колбэков может нарушиться; следующий кадр отправляют после колбэка предыдущего; при `ESP_ERR_ESPNOW_NO_MEM` нужна пауза |
| Энергосбережение | режим сна поддерживается только в режиме station; для узлов с внешним питанием не используется |

В описании `esp_now_send()` граница длины названа строго «меньше», а в обзоре — «не более 250». Проект считает безопасным размер не более 249 байт, пока граница не проверена на плате.

## Что не подтверждено и требует стенда

- Совместимость и одновременная работа STA и SoftAP на S3, правила выбора канала в этом режиме.
- Поведение при смене канала роутера и время восстановления связи.
- Число клиентов SoftAP.
- Потребление RAM и flash на зашифрованных пиров и на Wi-Fi вместе с HTTP-сервером.
- Число MAC-повторов, задержки, пропускная способность и ограничения частоты отправки.
- Работа ESP-NOW v2.0 на ESP32-C3 и допустимые версии ESP-IDF для неё.
- Поведение функций переключения канала `esp_now_switch_channel_tx()` и `esp_now_remain_on_channel()`.
- Влияние других сетей 2,4 ГГц и нагрузки Wi-Fi на потери пакетов.

## Как проект закрывает требования

| Требование | Подход |
|---|---|
| До 10 узлов | на Hub нужно увеличить число зашифрованных пиров с 7 по умолчанию, максимум по документации 17; значение проверяется измерением памяти |
| Работа без интернета | Standalone: точка доступа Hub и ESP-NOW на фиксированном канале |
| Шифрование | LMK на каждую пару плюс аутентификация и шифрование на уровне SPP; LMK не считается единственной защитой |
| Привязка | широковещательный поиск считается открытым; доверие создаёт процедура из [ADR-0004](adr/0004-pairing-and-keys.md) |
| Потеря и дублирование пакетов | номера сообщений, окно повторов, повторы с ограничением, идемпотентность по `command_id` |
| Восстановление после перезагрузки | Node помнит Hub и ключи; Hub помнит реестр; счётчики сообщений не повторяются при том же ключе |
| Контроль связи | периодические сообщения состояния и тайм-аут `offline` в `Registry.online` |
| Колбэки | только очередь, разбор в обычной задаче |

## Режимы сети Hub

**Standalone (MVP).** Hub создаёт точку доступа. Пользователь подключается к ней и открывает интерфейс. Узлы общаются с Hub по ESP-NOW на том же канале. Канал фиксирован и задаётся при первом запуске. Роутер и интернет не нужны. Время приходит из браузера или вручную ([ADR-0005](adr/0005-time-and-restart.md)).

**Home Network (этап F).** Hub подключается к домашней сети и отдаёт интерфейс в LAN. Радио одно, поэтому канал ESP-NOW определяется каналом роутера. Узлы должны уметь перейти на новый канал.

### Проект поиска канала (не реализован и не проверен)

1. Hub хранит текущий канал и сообщает узлам о плановом переходе до его выполнения.
2. Node хранит последний известный канал. Потеряв Hub на заданное время, он переходит в режим поиска: с ограничением частоты перебирает допустимые каналы, отправляя аутентифицированный запрос, который Hub может подтвердить. Во время поиска Node продолжает работать автономно по сохранённой конфигурации.
3. Запросы поиска защищены от повтора и не раскрывают секретов.
4. Список допустимых каналов определяется кодом страны.

### Переход между режимами

Переход Standalone ↔ Home Network выполняется как плановая смена канала с подтверждением пользователя. Hub проверяет связь с каждым узлом и показывает, кто не перешёл. Что отключённый узел вернётся сам, не гарантируется до испытаний.

## Бюджет памяти

Не измерен. Перед этапами C и D нужно измерить и записать в документацию:

- Node: свободная RAM при запущенном Wi-Fi и ESP-NOW, чтении датчика и работе насоса;
- Hub: свободная RAM и PSRAM при точке доступа, HTTP-сервере, десяти зашифрованных пирах и ведении истории;
- размеры разделов flash под настройки, журнал и два образа при OTA.

## Программа испытаний на стенде

1. Потеря пакетов и задержки на расстоянии и через стены при отключённой и нагруженной сети Wi-Fi.
2. Десять зашифрованных пиров на Hub: память, стабильность в течение суток.
3. Повторная доставка и потеря подтверждений: команда не должна запустить насос дважды.
4. Перезагрузка Hub, перезагрузка Node, отключение Hub на длительное время.
5. Смена канала Hub и возвращение узлов (для Home Network).
6. Устаревшая команда: полив не запускается после срока действия.
7. Совместимость обеих версий ESP-NOW на S3 и C3, если планируется использовать v2.0.
