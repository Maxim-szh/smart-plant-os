# План разработки

## Фаза 0 — контракт и аппаратные допущения (текущая)

Готовы архитектура, правила полива, форматы API v1, примеры сообщений, каталог кандидатов в модули и инструкция для контрибьюторов. Осталось выбрать конкретные платы и компоненты, снять электрические параметры, утвердить распиновку и бюджет flash/RAM. Нынешний HTML остаётся прототипом.

## Фаза 1 — один автономный узел

Прошивка ESP-IDF для S3 N16R8 и C3 Super Mini с общей предметной логикой и отдельными настройками платы. Один откалиброванный почвенный датчик, контроль воды в баке, один насос, ручной и пороговый автоматический режим, локальный HTTP API v1, ограниченный журнал событий. После включения насос выключен; ошибочные и устаревшие данные блокируют автоматический полив. Нужны стендовые и аппаратные проверки.

## Фаза 2 — единое приложение для нескольких узлов

Локальный координатор с реестром устройств и одним веб-интерфейсом. Он показывает состояния, пересылает команды и получает журнал после восстановления связи. Полив остаётся на узлах. Интерфейс отделяется от встроенных демонстрационных массивов и работает по контракту v1. Размещение координатора на NAS или другой машине решается после первого рабочего узла.

## Фаза 3 — расширения

Долгая история на microSD или NAS, экспорт, проверенная база растений, более сложные правила, датчики света и климата, Home Assistant через MQTT Discovery, обновления прошивки и ИИ-советы. Каждое расширение оформляется отдельной спецификацией и не должно нарушать автономность базового узла.

## Готовность к прошивке

- Выбраны точные экземпляры плат, объём flash, почвенный датчик, насос, его драйвер, датчик бака и питание.
- Для обеих плат утверждены контакты с учётом загрузочных, USB и занятых памятью выводов. Пока эта работа не сделана, в проекте нет «универсальной» распиновки.
- Измерены ток запуска насоса, производительность (мл/с), поведение при пустом баке и уровни сигнала датчика. Определены пределы настройки, не превышающие аппаратный максимум.
- Рассчитана таблица разделов flash, включая место для двух образов при OTA, если OTA включается в релиз; рассчитан размер локального журнала.
- Согласованы `spec/v1`, авторизация команд, первичная привязка узла, сетевое время и поведение после перезагрузки.
- Выбран и проверен на C3 и S3 защищённый транспорт API. Рассмотрены HTTPS на узле с закреплением сертификата в координаторе и защищённая первичная настройка через ESP-IDF Provisioning; [сетевое решение](SECURITY.md) содержит критерии выбора.
- Для всех кодов отказа из [WATERING.md](WATERING.md) есть сценарий проверки на стенде. Критичный результат — насос остаётся выключенным при неопределённом состоянии.

## Что намеренно не является условием фазы 1

Шесть растений на одной плате, исполняемый пользовательский псевдокод, прогноз роста, ИИ, Home Assistant, NAS, microSD и большой графический интерфейс непосредственно в памяти C3.
