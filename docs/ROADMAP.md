# План разработки

Целевая архитектура: ESP32-S3 Hub ↔ ESP-NOW ↔ ESP32-C3 Node ([ARCHITECTURE.md](ARCHITECTURE.md), [ADR](adr/README.md)). Работа идёт небольшими проверяемыми этапами. Ни один этап не считается завершённым без указания, что проверено статически, что собрано, что смоделировано и что ещё требует оборудования.

## Этап 0 — подготовка репозитория (выполнен)

Убрана дублирующая публикация Pages, обновлён `.gitignore` (артефакты сборки, ключи, дампы NVS).

## Этап A — архитектура (основа зафиксирована)

Роли Hub и Node, ESP-NOW и сетевые режимы, границы автономности, ADR 0001–0011. ADR-0004 (пользовательская привязка) и ADR-0009 (доступ браузера) остаются предложениями. ADR-0010 допускает ограниченный инженерный профиль с физическим USB provisioning, не выдавая его за завершённые этапы C/D. Код и документы сведены в [матрицу реализации](FIRMWARE.md).

## Этап B — протокол SPP

Реализованы ограниченный CBOR-кодек, версия кадра, AES-GCM, replay epochs, формат команд/событий/настроек, дедупликация и ограниченные повторы. Есть host-тесты и [векторы](../spec/spp/v1/vectors.json). Остались полный набор возможностей/метаданных для REST, независимое security review и испытания радиоканала.

Спецификация сообщений в `spec/spp/v1`, таблица числовых ключей CBOR, тестовые векторы, кодек и проверка, окно повторов, идемпотентность команд, срок действия команды, согласование версий и возможностей. Тесты на хосте и симуляция обмена Hub ↔ Node: повторная доставка, потеря пакета, отключение Hub, перезагрузка Node, пустой бак, неисправный датчик, отсутствие калибровки, лимиты, аварийная остановка, восстановление связи, конфликт версий конфигурации, недоступность хранилища, неподдерживаемая версия. Железо не требуется.

## Этап C — минимальная прошивка Node

Инженерная реализация добавлена и собирается на ESP-IDF v5.3.4. Профиль датчика — Capacitive Soil Moisture Sensor v1.2, GPIO не назначены по умолчанию. Ядро проверено на хосте. Этап не закрыт до проверки физического оборудования по [плану стенда](FIRMWARE.md#что-должно-быть-проверено-перед-настоящим-поливом).

Требует выбора версии ESP-IDF и сведений об оборудовании. Датчик почвы, контроль бака, драйвер насоса и локальная защита, ESP-NOW, хранение настроек, общие компоненты. Сборка в CI для ESP32-C3; поведение насоса при старте и сбросе проверяется только на стенде.

## Этап D — минимальная прошивка Hub

Добавлена инженерная прошивка: ESP-NOW, реестр, RPC, синхронизация времени, RAM-история, Standalone AP, HTTPS API и авторизация браузера. Минимальный `web/live.html` отделён от полного дизайн-прототипа. Пользовательская привязка, перенос полного дизайна и стенд AP + ESP-NOW ещё не завершены; сборка не заменяет испытания.

ESP-NOW, реестр узлов, Standalone-точка доступа, REST API по контракту v1 и первая панель в `web/index.html`. Установщик умеет задать домашний Wi-Fi Hub на фиксированном общем канале; длительные проверки совместной работы AP+STA+ESP-NOW и испытания на платах ещё впереди.

## Этап E — интеграция интерфейса

Рабочая панель Hub получает реальные данные через API, показывает состояние Node и позволяет выполнять доступные операции. Большой интерактивный макет сохранён отдельно в `web/prototype.html`; перенос его сценариев в рабочий интерфейс выполняется постепенно ([ADR-0008](adr/0008-ui-data-adapter.md)).

## Этап F — расширения

Полный доступ к панели в LAN с доверенным локальным именем TLS и автоматическая смена канала, microSD и расширенная история, OTA, Home Assistant через MQTT Discovery, дополнительные датчики (температура и влажность воздуха, освещённость, батарея, расход), ИИ-интеграции с подтверждением пользователя, проверенная база растений. Каждое расширение оформляется отдельной спецификацией и не нарушает автономность узла.

## Готовность к прошивке

- Выбраны точные экземпляры плат, объём flash, почвенный датчик, насос, его драйвер, датчик бака и питание. Для MVP предполагается питание Node 5 В, ориентир 5 В / 2 А; достаточность для конкретного насоса не утверждается без измерений.
- Для обеих плат утверждены контакты с учётом загрузочных, USB и занятых памятью выводов. Пока эта работа не сделана, в проекте нет «универсальной» распиновки.
- Измерены ток запуска насоса, просадка питания, производительность (мл/с), поведение при пустом баке и уровни сигнала датчика. Определены пределы настройки, не превышающие аппаратный максимум.
- Рассчитана таблица разделов flash, включая два образа при OTA, если OTA входит в релиз; рассчитан размер локального журнала и ресурс записи.
- Согласованы `spec/v1` и `spec/spp/v1`, привязка и ключи ([ADR-0004](adr/0004-pairing-and-keys.md)), доступ браузера ([ADR-0009](adr/0009-browser-access-to-hub.md)), время и поведение после перезагрузки ([ADR-0005](adr/0005-time-and-restart.md)).
- На стенде измерены ESP-NOW: потери и задержки, десять зашифрованных пиров на Hub и их память, поведение при высокой нагрузке Wi-Fi ([NETWORK.md](NETWORK.md)).
- Для всех кодов отказа из [WATERING.md](WATERING.md) есть сценарий проверки на стенде. Критичный результат — насос остаётся выключенным при неопределённом состоянии.

## Что намеренно не является условием MVP

Шесть растений на одной плате, исполняемый пользовательский псевдокод, прогноз роста, LLM и облачные подписки, мобильное приложение, Home Assistant, NAS, microSD, автоматическое переключение радиоканалов, OTA и полноценный Plug and Play оборудования.
