# Настройки ухода: проверка и сохранение

Реальный интерфейс использует прежние карточки и палитру. Пример `demo.html` остаётся отдельным. Эти функции не включают насос и не добавляют обход ограничений C3.

## Черновики

Редакторы растения, правила полива, точек калибровки и дневника предупреждают при закрытии кнопкой или Escape. Внутри приложения можно остаться или отказаться от изменений; при перезагрузке/уходе со страницы используется штатное предупреждение браузера, если браузер его поддерживает. Мобильная ОС может завершить вкладку без события, поэтому абсолютное сохранение черновика не обещается. Черновики остаются в RAM, ключи и пароли не записываются в localStorage.

Фоновые обновления показаний не заменяют открытый редактор. Переключение формы и обновление дневника тоже требуют решения пользователя. После подтверждённой записи черновик очищается. Закрытие окна не отменяет уже отправленную операцию; пока ждём ответ, отказ от черновика в диалоге недоступен. Формы вне диалогов первичной настройки не входят в этот механизм.

## Предварительная проверка

`web/care.js` повторяет текущие ограничения `sp_config_valid`: целочисленные диапазоны, порция не больше суточного лимита, две точки ADC с разницей не меньше 200, параметры подачи насоса и время, достаточное для порции. Для automatic_threshold обязательны обе калибровки. Режим этим редактором не меняется.

Предпросмотр показывает изменённые значения, режим, паузу, суточный лимит и оценку времени подачи с округлением вверх до миллисекунды. Это не расписание и не гарантия дозировки. Ошибки блокируют сохранение, отсутствие калибровки в ручном режиме объясняется отдельно. Окончательная проверка и commit выполняются на C3.

## Одновременное редактирование

Редактор использует ревизию, полученную при открытии. PUT config передаёт ту же ревизию в JSON и If-Match; Node атомарно проверяет её до изменения. Редактор калибровки больше не подменяет исходную конфигурацию свежим GET перед сохранением. Метаданные растения используют свою существующую ревизию Hub; дневник — ревизию записи.

409 оставляет введённые данные, блокирует повторное сохранение устаревшей формы и предлагает загрузить актуальные настройки. Автоматического слияния, очереди записи офлайн и повторов PUT нет. При сетевой неопределённости тоже сначала читают состояние. Никакого «последняя запись победила».

Успех настройки полива показывается только после ответа C3 на CONFIG. Нет отдельного промежуточного сохранения правила на Hub: при недоступном C3 приложение не обещает применить его позднее. Описание растения, наоборот, сохраняется на Hub и так подписано.

## Готовность и версии

Из раздела ухода или панели контроллера доступна проверка готовности: связь, объявленное оборудование, настройки, калибровки, актуальные показания, вода в баке, время, согласованные лимиты, занятость насоса и последнее решение защит. Неизвестное не считается исправным. Это снимок по API; он не доказывает качество монтажа и не заменяет проверку непосредственно перед запуском на Node.

Совместимость показывает версии Hub/C3, API 1.0, ABI Hub и поддержку OTA. Разные номера версий сами по себе не считаются несовместимостью. ABI C3 не передаётся отдельным полем, поэтому UI не утверждает его проверенным; конкретный образ проверяется на обеих платах. Неизвестная версия и недоступное устройство показаны явно.

В обновлении предварительно проверяются пара manifest/bin, профиль, ABI и запрет понижения версии. Текущий загрузчик Hub требует образ не старее своей версии; C3 дополнительно проверяет образ относительно своей. SHA-256 и заголовок проверяются при установке, сервер остаётся окончательным источником решения. Порядок миграции при будущем изменении протокола/ABI задаётся выпуском, не угадывается по сравнению номеров.
