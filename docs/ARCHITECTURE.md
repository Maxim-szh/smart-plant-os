# Архитектура

## Единица системы

Узел — одна ESP32 и одно растение. У него собственные `device_id`, `plant_id`, почвенный датчик, датчик наличия воды, насос, конфигурация и краткий журнал. Замена имени или адреса Wi-Fi не меняет ID. Перенос растения на другую плату — отдельная операция миграции, в которой сохраняется `plant_id`, но меняется `device_id`.

```text
датчики → нормализация и качество → состояние → правило полива → защита → драйвер насоса
                                      ↑                ↑
                                   настройки       команды API
                                      ↓                ↓
                                 журнал событий ← результат
```

Слой драйверов отличается для S3 и C3. Модель данных, проверки команд и логика решения должны совпадать. HTTP-обработчик не включает GPIO напрямую.

## Разделение ответственности

| Компонент | Отвечает за | Не отвечает за |
|---|---|---|
| Узел | измерение, калибровку, полив, защиту, локальный API, краткий журнал | общий каталог устройств, облачные советы |
| Координатор | реестр узлов, единый адрес веб-приложения, агрегирование, проксирование команд, синхронизацию событий | решение о разрешении полива |
| Веб-приложение | представление измерений и причин решений, настройки через API, подтверждение команды | вычисление фактического объёма, прямое управление GPIO |
| Адаптеры | будущий Home Assistant, NAS/microSD, экспорт | изменение защитных лимитов в обход API |

Координатор в фазе 2 будет локальной службой на постоянно доступном устройстве. В фазе 1 его контракт можно проверять заглушкой на компьютере; узел не зависит от неё. Веб-интерфейс для нескольких узлов обслуживается координатором. Минимальная страница узла служит для диагностики и первичной настройки, а не является второй полной версией приложения.

Чтобы интерфейс не переписывался при переходе от одного к нескольким растениям, координатор предоставляет список узлов и проксирует маршруты одного узла с префиксом `/api/v1/nodes/{device_id}`. Формат `State`, `Config`, `EventPage` и команд остаётся тем же. Координатор не подменяет последнюю известную оценку состоянием «сейчас»: недоступность узла сообщается отдельно.

## Данные и время

Настройки и калибровка хранятся на узле. Справочник видов — отдельный набор советов, не источник обязательных ограничений. История событий получает последовательный `seq` на каждом узле и `event_id`; координатор запрашивает события после последнего полученного `seq`. Пропуски после переполнения кольцевого журнала возвращаются явным кодом `cursor_expired`.

Время имеет качество `synced` или `unset`. Монотонный таймер нужен для максимального времени работы насоса и паузы после полива; календарное время требуется для суточного лимита и расписаний. После перезагрузки без достоверного времени автоматический полив заблокирован до синхронизации. Обрыв Wi-Fi после успешной синхронизации не сбрасывает внутренние монотонные таймеры.

NVS подходит для небольших настроек и калибровки; журналы и веб-ресурсы требуют отдельного бюджета разделов flash. microSD/NAS позднее получают копию событий, но не становятся единственной копией ограничений. Размеры разделов и интервалы записи пока не утверждены.

## Сеть и доверие

Узел доступен в локальной сети. Изменение настроек и команды насоса требуют привязки и авторизации. Конкретный способ первичной привязки и ротации ключа утверждается до сетевой реализации. Координатор хранит адреса и идентификаторы узлов, не ищет их через браузер. На уровне API ограничиваются размер сообщений, частота команд и время ожидания.

Команды получают стабильный `command_id`, чтобы повтор после сетевого тайм-аута не вызвал второй полив. Состояние команды и событие о результате берутся с узла. Для нескольких устройств нет глобального правила полива: каждый узел независим.

## Будущие интеграции

Home Assistant получит адаптер к тем же состояниям и командам. MQTT Discovery потребует постоянных `unique_id`, описания устройства и availability. Наличие связи с узлом и исправность его датчика — разные статусы. Долгая история на NAS или microSD потребляет события по курсору; потеря хранилища не останавливает базовый уход.
