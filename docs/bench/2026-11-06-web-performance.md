# Веб-интерфейс 0.6.1: передача ресурсов и отзывчивость

## Изменения

[Алгоритмы](../WEB-PERFORMANCE.md), [ADR-0025](../adr/0025-web-assets-and-progressive-refresh.md). Дизайн и шрифты сохранены. Gzip создаётся при сборке, браузер ревалидирует статические файлы по ETag. API остаётся no-store. Сад отображает каталог и выбранное растение до завершения всех необязательных запросов; стабильный DOM не заменяется на каждом фоне.

Все встроенные ресурсы: 640382 исходных байта, 344694 байта при согласовании gzip, включая неизменённые уже сжатые шрифты/PNG. Это не размер одного посещения: набор включает отдельный демонстрационный режим и мастер настройки.

## Физический S3 N8R2

Обновлён только Hub через HTTPS OTA с закреплённым сертификатом, без стирания NVS. Подтверждены версия 0.6.1, успешный запуск и SHA точного пакета. Каталог побайтово совпал с текущим снимком до обновления. C3 не прошивался, команды полива не отправлялись.

Пять последовательных GET на работающем устройстве:

| Ресурс | Исходные байты | Передано байт | Время ответа, мс | Повторный GET |

| / | 4669 | 1413 | 34 | 304, без тела |

Время — отдельная последовательная проверка на установленном TLS-соединении, не полная загрузка страницы и не обещание такого результата на другом роутере/телефоне. Начальный baseline первого запроса включал установление соединения, поэтому напрямую сравнивать его с этой таблицей нельзя.

Проверены побайтовое восстановление gzip в актуальные HTML/JS/CSS, собственные ETag вариантов, запрет gzip при q=0, отсутствие Content-Length/тела у 304, следующий ответ на том же keepalive-соединении, CSP/nosniff и один непротиворечивый Cache-Control. /api/v1/nodes с If-None-Match:* вернул обычный 200/no-store без ETag и Content-Encoding.

## На компьютере

- 20/20 native наборов, включая переговоры Accept-Encoding и сравнение ETag.
- Python-проверка детерминированной генерации и восстановления всех сжатых файлов.
- npm run check.
- Все восемь браузерных сценариев: настройка, привязка, OTA, системные службы, дневник/история, редакторы/калибровка, домашний интерфейс, производительность.
- Старый сценарий привязки обновлён до уже существующих минутного окна калибровки и обязательного обслуживания.
- При заблокированном device API карточки видны до его завершения, навигация работает. В одном прогоне 176 мс от начала навигации; это искусственный сценарий на компьютере, не измерение ESP32.
- Фоновое обновление не запрашивает каталог повторно в пределах TTL и сохраняет DOM неизменившихся настроек/навигации.
- Одновременные одинаковые GET используют один HTTP-запрос, возвращая независимые объекты. Поздний ответ опроса не возвращает сад после выхода.
- Сборки ESP-IDF 5.3.4: S3 N8R2, S3 N16R8, C3. N16R8 физически не проверен.

## Границы

Профиль проверен на одном физическом Hub. Проверки десяти реальных контроллеров и различных телефонов/роутеров остаются отдельным этапом. Холодная загрузка со всеми шрифтами не сводится к уменьшению одного JS-файла. Новых фоновых повторов записей, кеша API, Service Worker и изменения защит Node нет.
