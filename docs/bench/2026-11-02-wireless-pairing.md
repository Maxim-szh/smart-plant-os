# Беспроводная привязка C3 — 2026-11-02

Стенд: S3 N8R2 и C3 Super Mini, только USB, без нагрузок. Реальные MAC, идентификаторы и ключи не публикуются.

## Найденные проблемы

- После настройки Wi-Fi корень домашнего адреса ошибочно отправлял на /setup: ESP-IDF использует IPv6 listener и IPv4-mapped адрес, обработчик проверял только AF_INET. Добавлена обработка обеих форм и host-тест; после USB-обновления корень отдаёт 200 с app.js, без redirect.
- Discovery и HMAC-подтверждение обмена ключами прошли на железе, но телеметрия не появилась. Диагностика обеих плат показала отправку при нулевом приёме encrypted кадров. После защищённой доставки общего PMK Hub обе платы начали принимать корректные SPP-кадры. Полагаться только на ACK процедуры привязки было недостаточно.

## Выполнено

- S3 обновлён app-only, домашний Wi-Fi и индивидуальный ключ владельца сохранены. TLS проверяется по отпечатку локального access.json до отправки пароля.
- Тестовый C3 явно сброшен и установлен действием new-node, без заранее записанной связи с Hub. Его автономная идентичность и ожидающий ключ созданы при первом запуске.
- Реальный C3 найден по ESP-NOW, выбран через authenticated API. Hub принял ровно один запрос connect, обе платы сохранили связь и подтвердили ключи.
- Без повторного сброса установлен PMK envelope, восстановлен приём проверенных SPP-кадров на S3 и C3. У C3 после поиска каналов устанавливается канал роутера.
- Host: 8 сценариев C, включая P-256/HKDF (независимый Python-вектор), целостность каждого байта PMK envelope, повреждённые proof, сбой записи, перезапуск во время привязки и отсутствие повторных объявлений bound C3. Python: USB-мастер 6/6 и provisioning 5/5.
- Chromium/mock: основной интерфейс, ввод ключа, поиск, выбор C3, потеря ответа без повторного connect, ожидание online, мобильная ширина и инструкция обновления в настройках.

## Финальная проверка API и браузерного сеанса

- На домашнем адресе корень возвращает HTML приложения (200) с app.js/pairing.js. Мастер не открывается вместо растений.
- Реальный C3 online, GET его state отвечает 200; ответ проверен по публичной JSON Schema State через AJV.
- Домашний Wi-Fi подключён, setup_ap_enabled=false, при этом C3 остаётся online. При перезапусках плат связь восстановлена без повторного ввода ключей.
- Успешный вход выставляет Secure/HttpOnly/SameSite=Strict cookie на 900 секунд. Реальная cookie авторизует GET nodes без Bearer. Logout инвалидирует и cookie, и Bearer.
- Новый поиск не показывает уже привязанный C3; повтор connect для этого ID отклонён 409, ключи не менялись.
- Режим поиска, выбор, потеря ответа, ожидание online, отображение реального реестра на главной и повторный вход через cookie после reload проверены в Chromium/mock на мобильной ширине.
- Первый аппаратный прогон был разбит на первоначальную привязку и обновление той же связи с доставкой общего PMK. Позже по запросу владельца выполнен отдельный полный чистый прогон, описанный ниже.

- Chromium дополнительно проверил настоящий Hub: домашняя страница без redirect, реальный C3 online в основном приложении и диалоге, сохранение сеанса между страницами/reload. Снимки остаются локальными и не публикуют реальные идентификаторы устройства.

## Оставшиеся границы

Проверки реальных датчиков/насоса, несколько физических C3, RF DoS, независимый security review и отключение питания на каждой границе NVS commit не выполнялись. Первое подключение работает в профиле first_use_unverified — защиты от активного MITM на этом этапе нет, QR/PoP не реализованы по выбору владельца стенда. Изделие с нагрузками этим испытанием не аттестуется.

## Повторный чистый прогон после всех исправлений

По запросу владельца обе платы явно сброшены через проверенную область NVS. S3 N8R2 установлен из актуального пакета с новым ключом/сертификатом, без домашней сети и растений. Владелец с iPhone подтвердил вход в новый мастер, настройку домашнего Wi-Fi и переход в основное приложение. После этого C3 установлен действием new-node без NVS-образа связи и без паспорта Hub; владелец нашёл и подключил его из приложения, подтвердил состояние «На связи». Это полный первый обмен с автоматической доставкой PMK на актуальных прошивках, а не восстановление прежних ключей. Старые NVS не восстанавливались.

Выявлен и устранён нюанс повторной установки C3: после factory-reset старая прошивка с auto-identity могла заполнить пустую NVS раньше fresh-проверки. Теперь C3 остаётся в ROM bootloader после reset и всех read-only проб new-node до итоговой записи приложения. Аппаратная проверка flash ID/MAC/пустой NVS без старта приложения прошла; новый C3 успешно установлен. USB-тестов теперь 7/7, включая модель с автосозданием идентичности при каждом ошибочном промежуточном reboot.

После этого C3 перезапущен без записи flash/NVS. Владелец подождал 20–30 секунд и подтвердил повторное состояние «На связи» без поиска и перепривязки. Сеанс S3 и домашняя сеть при этом не сбрасывались.
