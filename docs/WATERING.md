# Полив и поведение при отказах

Документ определяет поведение первого работающего узла. Уставки для конкретных растений пока не подтверждены исследованиями; справочник видов предлагает значения, которые пользователь должен проверить и принять. Жёсткие аппаратные пределы не редактируются через обычный API.

## Режимы

- `manual` — насос запускается только по команде. Условие «почва сухая» не обязательно, все остальные проверки обязательны.
- `automatic_threshold` — узел измеряет откалиброванный `soil_index_pct` и предлагает порцию, когда значение ниже `dry_threshold_pct`. После полива действует `min_interval_minutes`; нельзя повторять полив только потому, что почва не успела отреагировать на воду.

Начальный режим после установки — `manual`. Включить автоматический можно только при успешной калибровке почвенного датчика и насоса, наличии достоверного датчика бака и времени. Перед автоматическим запуском требуется свежее показание почвы. Датчики света, воздуха, сезон, стадия роста, ИИ и текстовый алгоритм в v1 не влияют на разрешение насоса.

## Машина состояний

```text
idle → checking → running → completed → cooldown → idle
           └→ rejected       ├→ stopped → cooldown
                              └→ failed  → fault
```

Перед переходом в `running` последовательно проверяются: готовность устройства, датчик бака, калибровка насоса, календарное время, пауза после последнего полива, дневной лимит, лимит одной порции, максимальное время насоса, отсутствие активного полива. В автоматическом режиме дополнительно проверяются качество/возраст почвенного измерения и порог. Любой отказ имеет машинный код из [контракта](PROTOCOL.md).

Во время работы насос останавливается при достижении запрошенного объёма по калиброванному времени, максимальной длительности, команде остановки, исчезновении воды или аппаратной ошибке. Без расходомера `estimated_ml = run_ms × pump_calibration_ml_per_second / 1000`; это оценка, а не измеренный объём. При старте питания, перезапуске приложения и watchdog выход насоса должен физически переходить в выключенное состояние. Требуется внешний драйвер с выключенным состоянием по умолчанию; окончательная схема проверяется на стенде.

Пределы формата: порция 10–300 мл, дневной лимит 10–1000 мл, работа насоса не более 30 с, интервал между поливами не менее 60 мин. Это верхние/нижние границы API, **не утверждённые безопасные значения для любого насоса или растения**. Конкретная плата и насос могут иметь более строгие неизменяемые пределы. Настройка, нарушающая эти пределы, отвергается.

Суточный лимит считается по достоверному календарному времени; после перезагрузки с `clock_state: unset` запуск любого полива блокируется до получения времени. Потеря Wi-Fi при уже синхронизированных часах не останавливает узел. История расхода и время последнего полива должны переживать перезагрузку настолько, чтобы не сбрасывать лимиты; детали хранения проверяются до реализации.

## Сценарии проверки

| Ситуация | Ожидаемый результат |
|---|---|
| Сухая почва, вода есть, все проверки пройдены | Одна порция; событие решения, запуска и завершения |
| Почва ещё не достигла порога | Автополив не начинается, `soil_not_dry` |
| Датчик не откалиброван, неисправен или данные устарели | Автополив заблокирован, соответствующий код |
| Бак пуст или статус бака неизвестен | Насос не включается, `tank_empty` или `tank_unknown` |
| Нет калибровки насоса | Полив заблокирован, `pump_uncalibrated` |
| Время после перезагрузки неизвестно | Полив заблокирован, `clock_unset` |
| Достигнут дневной/разовый лимит | Команда отклонена без запуска |
| Повторён тот же `command_id` | Второго включения нет, возвращён прежний результат |
| Пришёл `stop` во время полива | Насос выключен, результат `stopped` |
| Отключены Hub, Wi-Fi, HA, NAS или microSD | Node продолжает разрешённый автономный режим по сохранённой конфигурации |
| Команда полива пришла после срока действия | Отклонение без запуска насоса; код причины добавляется необязательным расширением на этапе B, клиенты v1 трактуют незнакомый код как общий отказ |
| Пропало питание или произошёл watchdog во время полива | Насос физически выключен при перезапуске; событие восстановления/ошибки после старта |

Ручной режим не должен превращать неизвестное состояние в разрешение: он обходит лишь порог влажности. Любой внешний клиент получает те же причины отказа.

## Hub и автономность узла

Правила этого документа исполняет Node. Hub предлагает конфигурацию и передаёт запросы, но не включает насос и не ослабляет пределы ([ADR-0001](adr/0001-roles-hub-node.md)). Локальная конфигурация Node остаётся источником правил: при потере Hub он продолжает разрешённый автоматический полив только в пределах сохранённой конфигурации и при достоверных данных, иначе насос не включается. После перезагрузки без достоверного календарного времени автополив блокируется (`clock_unset`), защита суточного лимита не ослабляется ([ADR-0005](adr/0005-time-and-restart.md)). Команда ручного полива имеет срок действия и не ставится в очередь для недоступного узла. Различие `estimated_ml` и `measured_ml` и смысл `soil_index_pct` не меняются.
