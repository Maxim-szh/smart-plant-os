# Обновления без потери настроек

Обновление отличается от заводского сброса. Оно сохраняет NVS: Wi-Fi, ключ администратора, привязки, boot epochs, калибровку и защитный учёт воды. Старые копии NVS не восстанавливаются. Перед стендовыми обновлениями отключайте питание насосов/клапанов; USB остаётся подключённым.

## Один раз: переход со старой прошивки

1. Скачайте USB-пакет для **точного** профиля: C3 Super Mini, S3 N8R2 или S3 N16R8. Одинаковый ESP32-S3 не означает одинаковые flash/PSRAM.
2. Установите Python и зависимости по [инструкции](SETUP.md).
3. Подключите одну нужную плату по USB, закройте serial monitor.
4. Запустите `python tools/flash.py`, выберите **«Обновить прошивку с сохранением настроек»**, порт, профиль и каталог пакета. На macOS/Linux команда может называться `python3`.
5. Мастер проверит установленную разметку и пригодность прежнего приложения как резервного. Введите `UPDATE`.
6. Дождитесь записи и 30–90 секунд проверки запуска. Для C3 оставьте ранее привязанный Hub включённым: подтверждается защищённая связь. Обновите обе платы по очереди.
7. Откройте прежний домашний адрес Hub. Прежний ключ продолжает действовать. В настройках обновления должна отображаться разметка `ota-v1`.

Сначала кандидат записывается в отдельный слот. Затем обновляются bootloader, таблица разделов и otadata. Прежнее приложение остаётся на месте, область NVS не записывается. **Именно запись bootloader/таблицы не атомарна:** если отключить питание на этом шаге, может потребоваться восстановление через ROM bootloader по USB. Это не повод стирать NVS. Если прежний образ не помещается в резервный слот или разметка неизвестна, мастер останавливается.

Новая установка пустой платы уже использует два слота. Для неё миграция не требуется. Не используйте `idf.py flash` как способ обновления действующей OTA-установки: стандартный flash_args может перезаписать otadata/ota_0. Для обновления используйте мастер или веб-интерфейс.

## Через браузер: Hub

1. Откройте приложение в домашней сети и войдите с ключом владельца.
2. **Настройки → Обновление Hub**. Эта же кнопка доступна в мастере первого запуска после входа.
3. Выберите `manifest.json` и указанный в нём файл приложения `.bin` из одного пакета. Не выбирайте bootloader или NVS.
4. Нажмите **«Проверить и установить»**. Отправка идёт порциями, весь образ не размещается в RAM ESP32.
5. После загрузки подождите перезапуска и проверки. Браузер проверяет состояние, а не отправляет файл повторно.
6. При истечении сеанса войдите заново. При изменении IP откройте новый домашний адрес. Если работоспособность не подтверждена, загрузчик возвращает предыдущий слот.

## Через Hub: C3

1. Откройте растение → **Обновить прошивку**.
2. C3 должен быть на связи, уже иметь ota-v1 и сообщать возможность OTA. На старом C3 сначала выполните USB-миграцию.
3. Отключите автоматический полив в **«Настройке датчиков»**; активный полив и ожидание впитывания должны закончиться. Питание исполнительных устройств на время стендовых работ отключено.
4. Выберите manifest и приложение профиля `c3`.
5. Hub сохранит проверяемый образ в staging flash, затем передаст его через зашифрованный ESP-NOW. Это может занять несколько минут. Не выключайте Hub и C3.
6. «Передано 100%» ещё не означает успешный запуск. Дождитесь подтверждения после перезагрузки C3. После обновления автоматический режим сам не включается.

Потеря пакетов обрабатывается ограниченными повторами одного смещения. Потеря Hub в середине передачи не делает неполный образ загрузочным. Возобновление после перезапуска Hub пока не поддерживается: после тайм-аута C3 вернётся к обычной работе на прежней версии, передачу можно начать заново. Отказ/неизвестный результат отображается явно.

## Совместимость и доверие

Формат пакета 2, layout `ota-v1`, data ABI `1`, версии `major.minor.patch-abi1`. Проверяются SHA-256 всего файла, ESP image, chip ID, flash size, project name, размер слота и версия. Более старые версии отклоняются веб-обновлением. Профиль N8R2 не взаимозаменяем с N16R8. При несовместимом ABI сначала требуется отдельная процедура миграции; принудительного обхода проверки в UI нет.

Manifest и SHA-256 защищают от ошибки выбора/повреждения, но не являются криптографической подписью автора. Signed releases, Secure Boot, Flash Encryption и миграция на новый ABI — отдельная работа. В текущей модели обновление устанавливает авторизованный владелец из доверенного источника.

## Разметка

| Раздел | Hub N8R2/N16R8 | C3 |
|---|---|---|
| NVS | 0x9000, 0x20000 | 0x9000, 0x20000 |
| PHY | 0x29000, 0x1000 | 0x29000, 0x1000 |
| otadata | 0x2a000, 0x2000 | 0x2a000, 0x2000 |
| ota_0 | 0x30000, 0x200000 | 0x30000, 0x1e0000 |
| ota_1 | 0x230000, 0x200000 | 0x210000, 0x1e0000 |
| staging C3 | 0x430000, 0x1e0000 | — |

Форматы обмена — [спецификация обслуживания](../spec/maintenance/v1/README.md). Основание — [ADR-0018](adr/0018-ota-slots-and-confirmed-updates.md). Физические проверки фиксируются в [стендовых отчётах](bench/).

## Продолжение загрузки в 0.3

После неопределённого ответа нажмите «Проверить состояние». Продолжение предлагается только при совпадении исходного файла в памяти браузера, SHA-256, UUID, цели и смещения. Нажатие «Продолжить загрузку» — новое явное действие; автоматического повтора POST нет. Перезагрузка страницы не сохраняет файл.


### Достоверность результата после перезапуска

Служебная запись результата v2 содержит адрес кандидата, сеанс, SHA-256 файла и ELF-идентификатор. Адрес без идентификатора не доказывает откат: USB-обновление могло заменить содержимое раздела. Для v1 выполняется проверка полного работающего образа по сохранённому SHA-256; совместимая запись преобразуется только в памяти. Неподтверждённая история не отображается как успешный OTA или rollback. Это не меняет data ABI и не затрагивает настройки/привязки.
