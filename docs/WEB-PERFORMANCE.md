# Производительность веб-приложения, 0.6.1

Дизайн, шрифты и поведение полива не меняются. Улучшаются передача статических файлов и ожидание API.

## Статические файлы

`tools/build_web_assets.py` при сборке S3 создаёт gzip-представления HTML/JS/CSS/manifest и отдельные ETag для исходных и сжатых байтов. Встроенные исходники остаются для клиентов без gzip; WOFF2/PNG повторно не сжимаются. Генерируемый header находится только в build, не в Git. При изменении любого ресурса CMake пересоздаёт представления; на самой ESP32 компрессора нет.

Файлы получают `Cache-Control: public, no-cache`, `Vary: Accept-Encoding` и ETag. Браузер может хранить байты, но перед повторным использованием проверяет актуальность. Совпадение If-None-Match даёт 304 без тела; после OTA новый файл имеет другой ETag. API, сессии и перенаправление первого запуска сохраняют no-store. Ни Service Worker, ни кеш команд/телеметрии не добавлены.

ESP-IDF 5.3 httpd_resp_send всегда генерирует Content-Length. Для 304 отправляется ограниченный собственный заголовок через штатный httpd_send без Content-Length и тела. CSP и nosniff сохранены. Код учитывает частичные отправки. Установка заголовка через httpd_resp_set_hdr добавляет значение, а не заменяет его: поэтому no-store устанавливается только на API/redirect, без противоречивых дублей на статике.

Основание: [HTTP semantics](https://www.rfc-editor.org/rfc/rfc9110.html), [HTTP caching](https://www.rfc-editor.org/rfc/rfc9111.html).

## Ожидание данных

После получения реестра и каталога сад отображается сразу. Состояние выбранного растения запрашивается первым и появляется до необязательного описания оборудования и до завершения опроса всех остальных. Запросы к S3 остаются последовательными: оптимизация не создаёт десятки TLS-соединений и не перегружает очередь контроллера.

Фоновый опрос использует каталог до 30 секунд. Явное обновление после действий владельца получает каталог заново. Совпадающие GET в процессе выполнения делят один HTTP-запрос, но каждый потребитель получает собственный объект ответа. Завершённые ответы API не кешируются. Любая изменяющая операция разрывает объединение старых GET. Команды/записи не повторяются автоматически.

Если обновление уже выполняется, явные запросы объединяются в один следующий цикл; вызывающий код дожидается результата. Изменение сеанса не позволяет позднему ответу старого опроса снова показать сад после выхода.

Неизменившееся меню сохраняет DOM. Фоновый опрос не пересоздаёт неизменившийся экран. При обновлении карточек сохраняются существующие контейнеры истории/дневника, если контекст растения и каталог не изменились. Явные действия могут обновить их заново. Защита активных полей ввода и независимых черновиков сохранена.

## Проверка

- Native: согласование gzip/q=0/wildcard и ETag/weak/list/несовпадение вариантов.
- Python: детерминированная генерация и побайтовое восстановление каждого gzip-ресурса.
- Браузер: задержанный device API не блокирует показ карточек и навигацию; фоновые циклы не повторяют каталог; стабильный DOM и независимость объектов объединённого GET.
- Существующие сценарии входа, настройки, калибровки, черновиков и домашнего интерфейса проверяются отдельно.

Цифры в искусственно задержанном API-сценарии не являются временем загрузки с ESP32. Сравнение реального HTTPS записывается отдельно. C3 не требует обновления ради оптимизации веб-приложения.
