# Smart Plant OS

Открытая локальная система ухода за растениями: **ESP32-S3 Hub ↔ ESP-NOW ↔ до десяти ESP32-C3 Node**. Один Node обслуживает одно растение и отвечает за измерения, решение о поливе и защиту насоса, в том числе без Hub. Hub даёт единый веб-интерфейс и REST API, ведёт реестр узлов и историю. Hub определяет политику и координирует, Node проверяет и исполняет; веб-интерфейс, ИИ и интеграции не управляют насосом напрямую.

> **Статус: инженерная версия для стенда.** Прошивки C3 и S3 содержат локальную защиту, SPP/ESP-NOW, реестр сменных датчиков, HTTPS API и минимальный веб-интерфейс для реальных устройств. Полный дизайн `web/index.html` пока демонстрационный; на Hub используется `web/live.html`. Аппаратные испытания ещё не выполнены. Границы реализации — в [FIRMWARE.md](docs/FIRMWARE.md).

## Прошить для тестов

Начните с **[пошаговой инструкции для C3 и S3](docs/FLASHING.md)**. Мастер `tools/install.py` собирает прошивки и выполняет первичную установку Hub + до десяти C3 на Windows, macOS и Linux; нужен установленный ESP-IDF 5.3.4. Предусмотрены профили ESP32-S3 N16R8 и N8R2. GPIO насоса не назначаются, а секреты остаются в локальном `secrets/`. Там же описаны ручные шаги и безопасное обновление без перезаписи NVS.

Кратко, в терминале ESP-IDF: в `firmware/node` выполните `idf.py set-target esp32c3`, затем `idf.py build` и `idf.py -p PORT_C3 flash monitor`. Для Hub повторите в `firmware/hub` с `esp32s3` и `PORT_S3`. Замените обозначения портов своими. **Одной записи приложения недостаточно:** для первой установки выполните шаги настройки из инструкции. При последующих обновлениях NVS повторно не записывают.

## Принятые решения

- Hub — ESP32-S3 N16R8 или N8R2 (интерфейс, реестр, история на microSD позже); сборка выбирается по маркировке модуля. Node — ESP32-C3 Super Mini. Точная распиновка зависит от ревизии платы и будет утверждена перед работой с железом.
- Один Node — одно растение, один почвенный датчик, датчик воды в баке и один насос с внешним драйвером. Node работает автономно при потере Hub.
- Hub и Node общаются по ESP-NOW через отдельный протокол SPP. Публичный REST API `/api/v1` принадлежит Hub и сохраняет контракт v1. Home Assistant, мобильные клиенты и ИИ — будущие потребители этого API.
- Первый рабочий режим: ручной полив и автоматический полив по порогу индекса почвы с ограничениями. Home Network, microSD, расширенная история, OTA и ИИ запланированы на последующие этапы. Решения: [ADR](docs/adr/README.md).
- База видов растений пока [черновая](data/knowledge-base/plants.json), без проверки по источникам. Её значения не должны автоматически становиться безопасными настройками устройства.

## Что показывает прототип
Коллекция растений с уникальным рисунком для каждого вида (растение «с характером»: размер зависит от стадии, поникает и просит воды, когда сухо), два режима ухода («Умный» с советами по датчикам, стадии, сезону и статистике; «Вручную» с простым правилом или программой на псевдокоде; в прошивке v1 на насос будут влиять только ручной режим и порог), предложения сменить стадию, необязательный ИИ-помощник в настройках, рецепты ухода (применить, сохранить свой, поделиться файлом, импортировать), автоопределение стадии растения (по возрасту, расходу воды, свету и сезону), первый запуск (поиск устройства, датчики, комнаты, первое растение), напоминания «от вас» (долить воду, осмотр раз в неделю), страница растения (сейчас, история, о растении), стадии ухода, свой алгоритм полива, события, настройки (основные и продвинутые), база растений, мастера добавления растения и датчика, состояния «нет связи», «датчик не отвечает», «бак пуст», светлая и тёмная темы.

## Попробовать прототип
```bash
npm ci
npm run serve        # http://localhost:8080/web/
npm run check        # проверки базы, схем, примеров и скрипта
```
Или откройте `web/index.html` в браузере. Шрифты берутся с Google Fonts, без сети будут запасные.
