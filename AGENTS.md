# Работа над Smart Plant OS

Перед изменениями прочитайте [CONTRIBUTING.md](CONTRIBUTING.md), [план](docs/ROADMAP.md) и нужную спецификацию. Система состоит из Hub (ESP32-S3) и до десяти Node (ESP32-C3), связь по ESP-NOW; решения записаны в [docs/adr](docs/adr/README.md). Один Node обслуживает одно растение; полив и все защитные ограничения принадлежат Node, REST API принадлежит Hub. `web/index.html` пока содержит только демонстрационные значения. Форматы будущего API определены в `spec/v1`; меняйте схему, пример и документацию вместе. Проверяйте изменения командой `npm ci && npm run check`. Точные GPIO не назначайте без проверки конкретной ревизии платы. В коммитах используйте `Signed-off-by`.

Прошивки: `firmware/node`, `firmware/hub`, ESP-IDF v5.3.4. Общие правила — в `sp_core`, радио и железо — в `sp_platform`, JSON-адаптер — в `sp_api`; [SPP](spec/spp/v1/README.md) отдельно от публичного JSON. Драйверы добавляются через `sp_sensors`; назначение входом защитной логики явное. Полный демонстрационный дизайн — `web/index.html`/`web/app.js`; реальная первичная настройка — `web/setup.html`/`web/setup.js` и `sp_setup`. Для C-изменений обязательны host-тесты из [FIRMWARE.md](docs/FIRMWARE.md) и обе сборки. Первый запуск описан в [FLASHING.md](docs/FLASHING.md). Нельзя автоматически стирать NVS, менять формат safety blob без миграции, подменять резерв воды измеренным объёмом или считать USB-консоль реализованным REST. GPIO, секреты и аппаратные проверки не выдумываются. При обновлении статуса сверяйте всю матрицу архитектуры, а не только драйвер датчика.

Первый запуск и обновления: [SETUP.md](docs/SETUP.md), [ADR-0013](docs/adr/0013-setup-and-preserving-updates.md), [контракт настройки](spec/setup/v1/README.md). USB-мастер не стирает NVS при update и не заменяет непустой NVS в fresh-режиме. Новые C3 добавляются через приватный USB-файл привязки; существующие связи не ротируются повторным импортом. Перед публикацией проверьте `python tests/firmware/test_flash.py` и `python tests/firmware/test_provision.py`.
