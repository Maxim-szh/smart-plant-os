# Работа над Smart Plant OS

Перед изменениями прочитайте [CONTRIBUTING.md](CONTRIBUTING.md), [план](docs/ROADMAP.md) и нужную спецификацию. Система состоит из Hub (ESP32-S3) и до десяти Node (ESP32-C3), связь по ESP-NOW; решения записаны в [docs/adr](docs/adr/README.md). Один Node обслуживает одно растение; полив и все защитные ограничения принадлежат Node, REST API принадлежит Hub. `web/index.html` — реальный интерфейс; `web/demo.html` — изолированный пример. Форматы API определены в `spec/v1`; меняйте схему, пример и документацию вместе. Проверяйте изменения командой `npm ci && npm run check`. Точные GPIO не назначайте без проверки конкретной ревизии платы. В коммитах используйте `Signed-off-by`.

Прошивки: `firmware/node`, `firmware/hub`, ESP-IDF v5.3.4. Общие правила — в `sp_core`, радио и железо — в `sp_platform`, JSON-адаптер — в `sp_api`; [SPP](spec/spp/v1/README.md) отдельно от публичного JSON. Драйверы добавляются через `sp_sensors`; назначение входом защитной логики явное. Реальный дизайн — `web/index.html`/`web/app.js`/`web/views.js`, пример — `web/demo.html`/`web/demo.js`; реальная первичная настройка — `web/setup.html`/`web/setup.js` и `sp_setup`. Для C-изменений обязательны host-тесты из [FIRMWARE.md](docs/FIRMWARE.md) и обе сборки. Первый запуск описан в [FLASHING.md](docs/FLASHING.md). Нельзя автоматически стирать NVS, менять формат safety blob без миграции, подменять резерв воды измеренным объёмом или считать USB-консоль реализованным REST. GPIO, секреты и аппаратные проверки не выдумываются. При обновлении статуса сверяйте всю матрицу архитектуры, а не только драйвер датчика.

Первый запуск и обновления: [SETUP.md](docs/SETUP.md), [ADR-0013](docs/adr/0013-setup-and-preserving-updates.md), [контракт настройки](spec/setup/v1/README.md). USB-мастер не стирает NVS при update и не заменяет непустой NVS в fresh-режиме. Новые C3 добавляются через поиск из приложения; приватный USB-файл оставлен для ранних установок. Существующие связи не ротируются повторным импортом. Перед публикацией проверьте `python tests/firmware/test_flash.py` и `python tests/firmware/test_provision.py`.

Привязка C3 из основного приложения: [ADR-0015](docs/adr/0015-first-use-radio-pairing.md), `sp_pairing`/`sp_join_crypto`, `web/pairing.js`. Профиль first_use_unverified не защищён от MITM при первом обмене; не называйте его аутентифицированной привязкой. 202 означает принятие действия, успех UI требует online. Host-проверки включают `wireless_pairing`, `join_crypto`, `web_interface_routing`; браузерные — `npm run test:setup`.

Сеанс владельца: [ADR-0016](docs/adr/0016-browser-session-cookie.md), Bearer и короткая HttpOnly/Secure/SameSite=Strict cookie. PMK сети Hub доставляется C3 только в domain-separated AES-GCM-обёртке; предположение о независимых PMK не подтвердилось на стенде. Не сбрасывайте links/safety/replay для исправления радио.

## Реальный сад и обслуживание

Контракты: `docs/adr/0017-live-garden-and-maintenance.md`, `docs/adr/0018-ota-slots-and-confirmed-updates.md`, `spec/maintenance/v1/README.md`. Демо не использует реальный API. Новые датчики объявляют capabilities/единицы/качество/калибровку; GPIO не угадываются. Plant ID, device ID и radio slot не взаимозаменяемы. При OTA сохраняются NVS, safety/state_v1 и boot epochs. Не использовать `idf.py flash` для обновления действующего OTA-устройства. Изменения ABI требуют отдельной миграции и ADR. Проверки: native C, JSON Schema, USB-миграция и браузерный сценарий; физические нагрузки — отдельный стенд.

## Локальные службы 0.3

[ADR-0019](docs/adr/0019-local-system-services.md), [контракт](spec/system/v1/README.md) и [инструкция](docs/LOCAL-APP.md). Реальный интерфейс сохраняет исходный дизайн примера. Не загружать demo.js и фиктивные массивы в реальную панель; отсутствие данных показывается явно. Диагностический экспорт использует белые списки без секретов/адресов/имён растений. Резервная копия — только метаданные, импорт с предпросмотром, optimistic snapshot и одним commit. HEALTH16/bit64 необязательны для старых Node; не выдумывать reset/RSSI. Никаких фоновых повторов команд, Service Worker с API-кэшем или подмены лимитов при восстановлении. Настройки sp.ui.v1 не содержат токенов.

Профили растений: [ADR-0020](docs/adr/0020-descriptive-plant-profiles.md), [контракт и UI](docs/PLANT-PROFILES.md). Вид/стадия — метаданные Hub, не Config Node. Канонический справочник profiles.json генерирует JS и C-маски; не править generated-файлы отдельно. catalog/state_v1 не стирать: state_v2 имеет явную миграцию. Backup v2 включает growth_stage, v1 остаётся читаемым.

Личные службы 0.4: [ADR-0021](docs/adr/0021-trusted-browsers-and-care-history.md), [контракт](spec/garden/v1/README.md). Доверенные секреты — только HttpOnly cookie и digest store, не localStorage/backup. Сессии независимы; отзыв подтверждается commit. Дневник владельца отделён от safety events. История не усредняет missing/stale/fault и не пишет flash при чтении; checkpoint ограничен 15 минутами. Не обещать push при закрытом браузере и полный импорт дневника/истории. C3 для описательных функций не нужна. Demo остаётся отдельно до будущего удаления, объединять его с реальными данными нельзя.

Редакторы ухода: [ADR-0022](docs/adr/0022-care-editing-and-readiness.md), [правила UI](docs/CARE-CHECKS.md). Сохранять исходную ревизию на всё время редактирования, включая калибровку. Нельзя обновлять базу черновика GET перед PUT или автоматически повторять запись при неопределённом результате. Предпросмотр и готовность не включают насос. Проверки UI повторяют текущие ограничения ядра; при их изменении обновлять `web/care.js` и проверки вместе. [Стенд грунта](docs/SOIL-TESTS.md) — план без физических результатов.

Домашний UX 0.5: [ADR-0023](docs/adr/0023-home-rooms-journal-and-service.md), [контракт](spec/experience/v1/README.md), [визуальная система](docs/UX-HOME.md). Не заменять SVG макетом-картинкой; не подмешивать mock-данные тестового сервера в web. room — метаданные Hub с revision; быстрый ручной полив — только запись. Обслуживание — отдельное намерение Hub + CONFIG manual с исходной ревизией; finish никогда не включает automatic. Не объявлять active при offline/устаревшем CONFIG. Шрифты локальные с OFL, C3 их не включает.
