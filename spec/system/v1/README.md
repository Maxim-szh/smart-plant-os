# Локальные службы v1

[JSON Schema](schema.json), [примеры](examples/), [ADR-0019](../../../docs/adr/0019-local-system-services.md). Все endpoints принадлежат Hub, требуют обычного сеанса владельца и same-origin. Максимальный JSON body — 12288 bytes; Content-Type `application/json`. Неизвестные поля отклоняются. JSON Schema ограничивает число символов; дополнительно прошивка проверяет размер UTF-8 в bytes, корректность кодировки, отсутствие управляющих символов и дубликатов UUID.

## Диагностика

`GET /api/v1/diagnostics` возвращает `Diagnostics`. Данные формируются по белым спискам: Hub и его время работы/перезапуск/память, сеть, радио, состояние обновления и до десяти контроллеров. Отчёт не содержит паролей, радиоключей, SSID, IP, MAC, названий растений, полного каталога или дампа NVS. Диагностическое чтение не записывает flash.

Причины перезапуска: unknown, power_on, software, panic, interrupt_watchdog, task_watchdog, watchdog, deep_sleep, brownout, usb, other. Это сообщение SDK, а не доказательство неисправности оборудования. `power_on` не означает ошибку. Отсутствующие измерения/сведения имеют null, неизвестная версия — `unknown`. `health.age_ms` и возраст RSSI обязательны для оценки свежести. Online определяется свежестью STATE, наличие HEALTH само по себе не объявляет устройство online.

RSSI контроллера считывается Hub из метаданных реально принятого, проверенного SPP-пакета; это сигнал в точке приёма, а не оценка качества канала в процентах. received_packets учитывает все принятые ограниченные кадры, accepted_messages/header_rejections/authentication_rejections относятся к SPP; SPU1 обрабатывается отдельно. Их отношение не является процентом потерь. Счётчики относятся к текущему запуску; переполнение uint32 не является новым boot. Не выдавать RSSI домашнего Wi-Fi за сигнал ESP-NOW каждого C3.

### HEALTH, SPP kind 16

Новый необязательный диагностический тип 0.3.0-abi1, сообщение раз в 15 секунд. Ключи строго: 0=16,1=1 descriptor version,7 reset kind (0..10 в порядке списка выше),8 free heap bytes uint32,9 minimum free heap bytes uint32,10 accepted SPP messages uint32,11 authentication rejections uint32,12 TX callback timeouts uint32,14 uptime ms (0..2^53-1),23 radio enabled (0/1). Minimum heap не превышает текущий free heap. Ключи не имеют значений STATE в сообщениях другого типа. HELLO capability bit64 означает поддержку диагностики. Новое boot epoch сбрасывает кэш HEALTH на Hub. Старый Node может продолжать базовый обмен, но его диагностика остаётся null. Кадры зашифрованы и защищены от replay обычным SPP.

## Wi-Fi и восстановление

- `POST /api/v1/setup/wifi/scan` с `{}` — один асинхронный поиск, 202. Повторы запуска не выполняются автоматически.
- `GET /api/v1/setup/wifi/scan` — `Scan`, без запуска поиска. Фазы idle/scanning/completed/failed. Не более 20 уникальных SSID, 20 секунд на поиск, не чаще одного запуска за 30 секунд. Невидимые/непредставимые как строгий UTF-8 SSID не включаются в список; название можно ввести вручную, если оно соответствует профилю.
- `supported` означает канал 1..11 и WPA2 Personal / совместимый смешанный режим. Открытые, enterprise, WPA-only и WPA3-only сети не предлагаются как поддерживаемые. Это профиль текущего изделия, а не предел ESP32.
- `POST /api/v1/setup/recovery` с `{}` — 202, открыть AP SmartPlantOS на 5 минут, пароль smartplantos. Ключ владельца не меняется. Отказ —409 recovery_unavailable.

Проба новой сети по прежнему `POST /setup/wifi` сначала проверяется, затем сохраняется. При ошибке/тайм-ауте восстанавливается предыдущая конфигурация. Во время сканирования/пробы другие setup-изменения и OTA begin запрещены. Во время OTA, отвязки или ожидающей операции pairing поиск запрещён. SDK Wi-Fi callback только выставляет событие; main task собирает ограниченный список.

Setup Status дополнен необязательными `rssi_dbm` (integer или null) и `last_disconnect_reason` (NONE/AP_NOT_FOUND/AUTH_FAIL/HANDSHAKE_TIMEOUT/ASSOC_FAIL/BEACON_TIMEOUT/AUTH_EXPIRED/OTHER). IP и SSID остаются на авторизованной странице сети, но исключены из диагностического отчёта.

## Резервная копия

`GET /api/v1/backup` возвращает `Backup`: format=`smartplantos.settings`, format_version=2, plants (0..20). Запись: plant_id UUIDv4, name (1..80 UTF-8 bytes), room (0..80 UTF-8 bytes), species_id (null или 1..40 ASCII `[a-z0-9-]`), growth_stage (null или код стадии). Версия 1 по-прежнему принимается без поля стадии: у существующего растения стадия сохраняется, если вид не изменился; при смене вида или создании записи стадия остаётся неизвестной. Экспорт всегда версии 2. Имя не может состоять только из пробелов. UUID не дублируются.

Экспортируются только метаданные. Привязки и их история, device IDs, ключи, сетевой пароль, GPIO, калибровка, управляющий Config, защитные лимиты/учёт воды и boot epochs отсутствуют. Настройки внешнего вида хранятся локально в браузере и также не входят в копию.

1. `POST /api/v1/backup/preview` с `{backup:Backup}` возвращает `BackupPreview`, не записывая NVS. Snapshot — SHA-256 текущего каталога, средство optimistic concurrency, не токен доступа. Changes показывает create/update/unchanged и прежние имя/комнату.
2. `POST /api/v1/backup/restore` с `{backup:Backup,snapshot:<64 lowercase hex>,confirm:true}` повторно проверяет файл и снимок. Несовпадение —409 backup_preview_expired. Неверный файл —400 backup_invalid, ошибка commit —503 storage_fault. При ошибке каталог в памяти не подменяется.
3. Изменения применяются одной записью каталога и одним NVS commit. Нулевые изменения не вызывают запись. Существующие связи сохраняются. Новые растения создаются без контроллеров и без истории привязок; новый Hub не получает ключи старого.

После восстановления привяжите свежий C3 к нужному сохранённому растению. При полном каталоге допускается свежий контроллер без временной строки растения, только если у него нет существующей идентичности растения и истории привязки. Это предотвращает тупик ёмкости при переносе 20 растений; не разрешает присвоение контроллера другого растения.

## OTA и интерфейс

Status обновления дополнен `image_sha256` и `target_device_id` (hub/DeviceId/null). Явное продолжение браузерной загрузки разрешено только для uploading при совпадении UUID, SHA, цели, размера и принятого offset с имеющимся в памяти файлом. После перезагрузки страницы файл автоматически не восстанавливается. Нет повторных POST, фоновой очереди команд или обещания продолжения радиопередачи после reboot Hub.

Реальный и демонстрационный интерфейсы используют исходную визуальную композицию. Реальная панель не загружает demo.js, PLANTS или фиктивную историю. Отсутствие событий отображается как «Событий нет», ошибка чтения — как недоступность истории, отсутствие датчика — как отсутствие датчика. Значение 0 показывается только при получении настоящего нуля. Внешний вид — локальные настройки `sp.ui.v1`, не секреты доступа. Manifest/иконки добавляют возможность установки браузером; Service Worker и offline-кэш команд отсутствуют.

В предпросмотре переноса отображаются также старые и новые вид/стадия. Размер JSON-ответа ограничен 24576 bytes; файл импорта в браузере — 16384 bytes. Сервер ограничивает повторно сериализованный запрос 12288 bytes. Граничный экспорт 20 растений с максимально экранированными именами проверяется host-тестом.
