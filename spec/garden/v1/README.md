# Личные устройства, дневник и история v1

[Схема](schema.json), [примеры](examples/). Все маршруты требуют действующего владельческого сеанса, HTTPS и прежних same-origin проверок. Нет облака, фонового исполнения программ или GPIO из этих служб. Ошибки используют общий Error API; неверная revision — 409, неверные поля — 422/400, недоступное хранилище — 503, заполненный дневник — 507.

## Доверенные браузеры

`POST /api/v1/session`: password, необязательные remember (по умолчанию false), device_name (1..48 UTF-8 bytes, без управляющих символов). Старый запрос только password продолжает создавать временный сеанс на 900 секунд. До восьми независимых временных и восьми доверенных браузеров. Новая сессия не вытесняет другое устройство. Повторный вход этого же браузера заменяет его собственный допуск.

Для remember=true сервер выставляет `sp_session` cookie: Secure, HttpOnly, SameSite=Strict, Path=/, Max-Age=31536000. Ответ содержит token=null, expires_in=31536000, trusted=true: долговременный секрет не отдаётся JS. Для временного входа остаётся Bearer token и cookie на 900 секунд. Долговременный допуск сервер считает действующим до отзыва; год — срок cookie браузера. Хэш допусков находится в web_access/state_v1, связан с отпечатком текущего owner key. Секреты cookie и сам ключ в localStorage/sessionStorage не помещаются, по каждому запросу flash не записывается.

`GET /api/v1/sessions` возвращает BrowserDevices: только id, name, trusted, current, expires_in (null для постоянного допуска). `PUT /api/v1/sessions/{id}` принимает RenameBrowser. `DELETE` этого адреса отзывает доступ и возвращает current_revoked. `DELETE /api/v1/session` отзывает текущий допуск; ошибка commit не выдаётся за успешный выход. `DELETE /api/v1/sessions` с `{confirm:true}` явно сбрасывает только доступы браузеров, в том числе позволяет восстановить повреждённый список после временного входа с ключом. Эти данные не включаются в резервные копии или диагностические отчёты.

Cookie привязана к адресу и профилю браузера. После очистки данных, инкогнито, смены адреса Hub или отзыва нужен новый вход. AP и домашний IP — разные адреса, для них действуют отдельные cookie. Физическая/криптографическая аттестация телефона не заявляется. Передача доверия между разными адресами без повторного ввода — отдельная будущая функция.

## Дневник

`GET /api/v1/plants/{plant_id}/diary?after=0&limit=32` возвращает DiaryPage. `after` — uint32 seq, limit 1..32, порядок параметров фиксирован. Каталог подтверждает существование UUID, связь C3 не требуется. `GET /api/v1/reminders?after=0&limit=32` возвращает ту же страницу для невыполненных напоминаний всех растений.

`POST /api/v1/plants/{plant_id}/diary` принимает NewDiaryEntry. UUIDv4 entry_id генерируется браузером один раз до отправки. Повтор с тем же содержимым возвращает существующую запись; другое содержимое с этим UUID — 409. kind: repot/fertilize/prune/move/stage/note/reminder. note — 0..160 UTF-8 bytes, для note/reminder обязательно непустое значение. at_ms — время действия, введённое человеком, а не измеренное датчиком. remind_at_ms обязательно для reminder и null для остальных видов. Допустимый календарный диапазон 2024–2100. Часовой пояс учитывается браузером при переводе местного ввода в Unix UTC milliseconds.

`PUT /api/v1/plants/{plant_id}/diary/{entry_id}` принимает UpdateReminder (revision, done), действует только на reminder. `DELETE` принимает DeleteDiaryEntry (revision), удаление требует явного подтверждения UI. Изменения выполняются одним commit care/state_v1, после успешной записи обновляется RAM. До 64 записей на Hub; автоматического удаления нет. Дневник связан с plant_id, не с radio slot или device_id. Браузер может экспортировать все страницы растения в отдельный JSON-файл. Импорт такого файла пока не реализован; это не формат backup профилей v2.

Напоминания показываются внутри открытого приложения, их срок сравнивается с часами браузера. Доставка при закрытом браузере, push и системные уведомления не реализованы. Ошибки/неопределённый результат не вызывают автоматический повтор изменяющего запроса.

## История измерений

`GET /api/v1/plants/{plant_id}/measurements?period=day&metric=soil_index` — Measurements. period day/week; metric soil_index/air_temperature/air_humidity/illuminance. Запрос сравнивает последние 24 часовых окна с предыдущими 24 либо семь календарных UTC-дней с предыдущими семью. Текущие час/день неполные; samples показывает фактическое покрытие. Это средние имеющихся исправных наблюдений, не оценка всего периода.

Hub берёт не более одного наблюдения в минуту на растение/показатель. Только online, quality=ok и свежий источник участвуют в среднем. Ошибки, старые значения и отсутствие связи не превращаются в ноль. Для дополнительных датчиков выбирается первый объявленный slot нужного kind. Смена контроллера/slot помечается controller_changed; смешанный час не выдаётся за однородное измерение. Среднее/минимум/максимум сохраняются в канонических единицах; °F — только отображение.

Хранилище measurements: кольцо h00..h47 (48 часов), d00..d13 (14 дней), до десяти растений и четырёх показателей в каждом bucket. Каждый blob версии 1 проверяется отдельно. Накопление идёт в RAM, checkpoint не чаще одного раза в 15 минут при изменениях; час также сохраняется при смене окна. Незавершённые последние 15 минут при потере питания могут потеряться. Суточные агрегаты восстанавливаются из доступных часовых checkpoint при запуске; большие пропуски не заполняются вымышленными значениями. Повреждение/ошибка записи показывается как storage_available=false, а не стирает каталог, ключи или защитное состояние C3.

До достоверного времени история не записывается. `GET /api/v1/time` возвращает TimeStatus. Открытое авторизованное приложение один раз проверяет время и, только если оно unset, предлагает Hub часы браузера через существующий POST /time. Неопределённый ответ автоматически не повторяется. Уже установленные часы не перезаписываются этим действием. При времени раньше сохранённой истории clock_state=rollback, запись приостановлена. Время и история не заменяют проверки безопасности Node.
