# Домашний уход v1

Новые маршруты доступны только владельцу. Общие ошибки и правила If-Match не меняются.

## Дневник

`GET /api/v1/diary?after=0&limit=32` возвращает существующий `DiaryPage` из garden/v1 для всех растений, включая архивные. Максимум 64 записи, пагинация по seq. Запись по-прежнему выполняется через `/plants/{plant_id}/diary`. Быстрый «Полил вручную» — подтверждаемая пользователем запись kind=note с текстом «Полил вручную»; не команда насосу и не изменение лимитов/защит. Подкормка/пересадка используют существующие kinds.

## Обслуживание

`GET /api/v1/nodes/{device_id}/care-service` возвращает:

```json
{"schema_version":1,"device_id":"spo-010203040506","plant_id":"01020304-0506-4008-800a-0b0c0d0e0f10","requested":false,"phase":"inactive","config_revision":7,"mode":"manual"}
```

phase: inactive — отметки нет; active — отметка есть и ручной режим подтверждён текущим CONFIG/STATE; pending — запрос обслуживания сохранён, ручной режим не подтверждён; unverified — нет связи/актуальной конфигурации/достоверного хранилища (ошибка хранилища отдаётся 503). При недостоверной конфигурации mode и config_revision равны null. UI не выдаёт последнее известное состояние за действующую паузу.

`POST /api/v1/nodes/{device_id}/care-service` — ровно `{schema_version:1,action:"start"|"finish",revision:uint32}`. Нужны online, прочитанный CONFIG, исходная ревизия и выключенный насос. start сначала сохраняет намерение на Hub, затем передаёт обычную CONFIG с automatic=false и прежними калибровками/лимитами через CAS Node. Успех требует ответа Node. Если уже подтверждён ручной режим, новых команд не требуется. Потеря ответа/отказ не превращается в успех: GET показывает pending/unverified до чтения текущего CONFIG/STATE. Автоматического повтора POST нет.

finish удаляет только отметку Hub, требует подтверждённого актуального ручного режима и совпадающей ревизии. НИКОГДА не включает automatic. Автополив после обслуживания пользователь настраивает отдельно. Таймера и автоматического возобновления нет. Изменение конфигурации другим клиентом, перезагрузка, потеря связи и смена контроллера не разрешают фоновое включение.

Намерение хранится отдельно в NVS Hub care_pause, по device+plant, формат 18 байт: version=1, UUID растения 16 байт, requested=0/1. Это не safety/state_v1, не часть backup метаданных. Повреждение store не исправляется стиранием. Записи не меняют структуру Node/NVS/SPP. При восстановлении/замене связь с другим plant UUID не наследуется.

## Комнаты и добавление

Группы строятся по существующему полю room метаданных Hub. Перенос растения использует PUT plant с исходной revision, не меняет CONFIG. Свёрнутость/фильтр/порядок комнат — ограниченные настройки конкретного браузера, без ключей и команд. Пустая комната показывается как «Без комнаты».

Добавление нескольких C3 последовательно: поиск → привязка одного → подтверждённый online → имя/комната/вид → сохранение метаданных → «Добавить ещё». Никакой групповой привязки без выбора, фоновых повторов и фиктивного setup_stage=3. Оборудование настраивается отдельно.
